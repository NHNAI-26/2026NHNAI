# 발사 결과 이벤트 기획

> 상태: 보조 기획 초안
> 목적: 발사 성공/부분 성공/실패 뒤에 나올 수 있는 단발 이벤트를 정의한다.
> 기준 문서: `docs/artemis-2026-gdd/05_테스트공개성_설계보정_확률.md`, `docs/artemis-2026-gdd/08_로켓_발사.md`, `docs/artemis-2026-gdd/12_밸런스_데이터표.md`

## 1. 사용 원칙

발사 결과 이벤트는 발사 판정을 바꾸지 않는다. 이제 발사는 실제 물리 시뮬레이션으로 우주선을 날려 판정한다. 이 문서의 이벤트는 결과 보고서 이후에 붙는 운영 효과다.

한 발사에는 결과 이벤트를 최대 1개만 적용한다. 여러 효과를 겹치면 원인 파악이 흐려지고 구현도 빨리 커진다.

이벤트 효과는 아래 범위 안에서만 둔다.

- 즉시 연구비 증감
- 분기 연구비 증감
- 분기 소모 또는 분기 절약
- 엔진 프리셋 완성도 증감
- 엔진 프리셋 스탯 점수 증감
- 다음 설계 진입 비용 또는 설치 비용 증감
- 특정 미션 재시도 비용 보정
- UI에 표시할 짧은 뉴스/내부 메모

이 문서에서는 `예상 성공도`, `설계 평가`, `위험도`, `성공률 보정`을 쓰지 않는다. 현재 게임에서 의미 있는 장기 자원은 돈, 시간, 엔진 완성도, 엔진 스탯 점수다.

엔진 완성도와 스탯 상승은 "발사 데이터를 연구에 반영했다"는 형태로만 준다. 한 이벤트가 여러 엔진을 크게 키우면 연구 행동이 약해지므로, 보통 이번 발사에 가장 많이 기여한 엔진 프리셋 1개만 대상으로 한다.

## 2. 발생 기준

이벤트 풀은 발사 등급과 테스트 공개성으로 먼저 거른다.

| 등급 | 기본 이벤트 성격 |
|---|---|
| S | 큰 성공, 후원, 일정 단축 |
| A | 안정 성공, 신뢰 증가 |
| B | 아슬아슬한 성공, 제한 보상 |
| C | 부분 성공, 데이터 회수, 재시도 보조 |
| F | 실패, 손실, 신뢰 하락, 복구 선택 |

공개 테스트는 언론, 후원, 평판 이벤트가 잘 나온다. 비공개 테스트는 내부 데이터, 비용 절감, 조용한 복구 이벤트가 잘 나온다. 최종 미션은 공개성 없이 전용 이벤트만 사용할 수 있다.

권장 선택 방식:

```text
가능 이벤트 목록 필터링
1. 등급 조건
2. 공개/비공개/최종 미션 조건
3. 미션 조건
4. 사고 ID 조건
5. 같은 이벤트 연속 발생 방지
6. 가중치 랜덤 1개 선택
```

MVP에서는 랜덤 없이 등급별 첫 번째 적합 이벤트를 골라도 된다.

스탯 보상 대상 엔진은 아래 순서로 고른다.

1. 이번 발사에 설치된 엔진 중 개수가 가장 많은 프리셋
2. 같으면 총 연소 시간이 가장 긴 프리셋
3. 그래도 같으면 설치 비용이 먼저 계산된 프리셋

## 3. 이벤트 목록

### 3.1 `SponsorBoost` - 후원 기관 추가 지원

발생 조건:

- 등급 `S` 또는 `A`
- 공개 테스트
- 최종 미션 제외

표시 문구:

> 공개 발사 장면이 크게 퍼졌다. 후원 기관이 다음 시험 예산을 조금 더 열어 준다.

효과:

- 즉시 연구비 `+300`
- 분기 연구비 `+50`

구현 메모:

- 기존 등급 보상과 공개 테스트 배율을 적용한 뒤 추가 보상으로 더한다.
- 단순 수치 이벤트라 UI와 저장 데이터만 있으면 된다.

밸런스 의도:

- 공개 테스트의 높은 위험을 성공 보상으로 확실히 느끼게 한다.
- S/A 성공에만 주어 실패 반복 도박을 막는다.

### 3.2 `CleanTelemetry` - 깨끗한 비행 데이터

발생 조건:

- 등급 `S` 또는 `A`
- 사고 없음 또는 경미한 경고만 발생

표시 문구:

> 텔레메트리가 깨끗하다. 연구팀이 다음 엔진 개선 실험을 바로 진행할 수 있다.

효과:

- 대상 엔진 프리셋 완성도 `+5`
- 대상 엔진 프리셋의 가장 낮은 스탯 `+4`
- 대상 엔진 프리셋의 다음 일반 연구 1회는 분기를 소모하지 않음

구현 메모:

- 완성도와 스탯은 각각 `100`을 넘지 않는다.
- 가장 낮은 스탯이 여러 개면 아래 우선순위를 쓴다: 연료 탱크 용량, 냉각 능력, 최대 출력, 점화 신뢰도.
- 무료 시간 효과는 비용 면제가 아니다. 연구비는 정상 지불한다.

밸런스 의도:

- 좋은 발사에서 좋은 데이터를 얻는 느낌을 준다.
- 연구 행동보다 작게 주어 보조 성장으로만 둔다.
- 드문 성공 보상으로 시간 1분기를 아끼게 한다.

### 3.3 `PublicPressure` - 공개 성공 뒤 일정 압박

발생 조건:

- 등급 `B`
- 공개 테스트
- 현재 연도 `2025`년 이전

표시 문구:

> 성공은 했다. 하지만 공개 약속이 커졌다. 다음 시험은 빨리 보여 달라는 압박이 붙었다.

효과:

- 즉시 연구비 `+250`
- 다음 행동이 `대기`면 분기 연구비 `-50`
- 다음 행동이 발사 미션이면 설계 진입 비용 `-100`

구현 메모:

- 새 선택지를 만들지 않는다.
- 상태 플래그 하나를 저장하고 다음 행동에서 한 번만 소비한다.

밸런스 의도:

- 공개 테스트는 돈이 되지만 운영 압박도 있음을 보여준다.
- B 성공을 S/A와 다르게 만든다.

### 3.4 `NearMissInspection` - 근접 사고 점검

발생 조건:

- 등급 `B` 또는 `C`
- 사고 ID가 `StructuralStress`, `GuidanceDrift`, `CutoffTooLate` 중 하나

표시 문구:

> 큰 사고는 피했다. 하지만 같은 설계를 그대로 쓰면 다음 시험에서 위험이 커진다.

효과:

- 다음 설계 진입 비용 `-150`
- 대상 엔진 프리셋 완성도 `+3`

구현 메모:

- "점검 지원"으로 설계 진입 비용만 줄인다.
- 완성도 상승은 사고 분석 데이터 보상이다.

밸런스 의도:

- 부분 성공이나 아슬아슬한 성공도 완전 낭비가 아니게 한다.
- 실패 원인과 재시도 동선을 연결한다.

### 3.5 `RecoveredPayload` - 시험 장비 회수

발생 조건:

- 등급 `C`
- 비공개 테스트
- 사고 ID가 `Crash`가 아님

표시 문구:

> 시험은 중단됐지만 장비는 회수했다. 내부 분석으로 재시도 비용을 줄일 수 있다.

효과:

- 같은 미션 다음 재시도 때 설치 비용 총합 `-20%`
- 할인 상한 `300`

구현 메모:

- 엔진 개별 가격을 바꾸지 않는다.
- 발사 확정 때 총 설치 예약 비용에 할인액을 한 번 적용한다.

밸런스 의도:

- 비공개 테스트의 안전한 성격을 강화한다.
- C 등급이 다음 미션 해금만 주는 밋밋한 결과로 끝나지 않게 한다.

### 3.6 `PadDamage` - 발사대 손상

발생 조건:

- 등급 `F`
- 사고 ID가 `Overheat`, `StructuralStress`, `Crash` 중 하나

표시 문구:

> 발사대가 손상됐다. 다음 시험 준비에 추가 정비가 필요하다.

효과:

- 즉시 연구비 `-200`
- 다음 설계 진입 비용 `+150`
- 이번 발사에 사용한 엔진 중 무작위 1개 프리셋 완성도 `-3`

구현 메모:

- 비용 부족으로 음수가 되지 않게 기존 연구비 하한 처리와 같은 방식을 쓴다.
- 추가 분기 소모는 넣지 않는다. 48시간 범위에서는 너무 무겁다.
- 완성도는 `0` 아래로 내려가지 않는다.

밸런스 의도:

- 큰 실패의 손맛을 만든다.
- 하지만 한 번 실패했다고 캠페인이 바로 망하지 않게 수치를 작게 둔다.

### 3.7 `QuietLessons` - 조용한 실패 분석

발생 조건:

- 등급 `F`
- 비공개 테스트

표시 문구:

> 밖에는 알려지지 않았다. 실패 데이터는 남았다. 같은 실수를 한 번 줄일 수 있다.

효과:

- 대상 엔진 프리셋 완성도 `+4`
- 대상 엔진 프리셋의 사고 연관 스탯 `+3`
- 공개/비공개 기본 실패 손실은 그대로 적용한다.

구현 메모:

- 사고 ID가 `IgnitionFailure`면 점화 신뢰도, `Overheat`면 냉각 능력, `FuelStarvation`이면 연료 탱크 용량, `ThrustLoss`면 최대 출력에 더한다.
- 매핑되지 않는 사고는 가장 낮은 스탯에 더한다.

밸런스 의도:

- 비공개 실패가 덜 아프고 학습으로 이어지는 느낌을 준다.
- 공개 테스트 실패와 명확히 갈린다.

### 3.8 `MediaBacklash` - 공개 실패 역풍

발생 조건:

- 등급 `F`
- 공개 테스트
- 최종 미션 제외

표시 문구:

> 공개 실패가 크게 보도됐다. 당분간 후원 기관의 반응이 차갑다.

효과:

- 분기 연구비 `-100`
- 다음 공개 테스트 보상 배율 `-0.25`
- 보상 배율 감소는 1회만 적용한다.

구현 메모:

- 비공개 테스트를 선택하면 배율 감소는 적용하지 않고 사라진다.
- 플레이어가 다음에는 비공개로 숨을 고를 이유를 만든다.

밸런스 의도:

- 공개 테스트 실패를 확실히 위험하게 만든다.
- 그래도 다음 발사가 불가능해지는 잠금은 없다.

### 3.9 `FinalProof` - 최종 검증 인정

발생 조건:

- 미션 ID `LowPowerZoneHold`
- 등급 `S`, `A`, `B`

표시 문구:

> 저전력 검증이 인정됐다. 아르테미스 발사 체계가 최종 통과했다.

효과:

- 게임 승리
- 최종 보고서에 `효율 검증 통과` 배지 표시
- 대상 엔진 프리셋 완성도 `+10`
- 대상 엔진 프리셋의 가장 낮은 스탯 `+5`

구현 메모:

- 이미 최종 승리 조건이 B 이상이므로 새 판정은 만들지 않는다.
- 엔딩 이후 계속 플레이가 없다면 수치 보상은 기록용이다.

밸런스 의도:

- 최종 미션 성공을 일반 발사 성공보다 분명하게 보이게 한다.
- 보상보다 엔딩 전환이 핵심이다.

## 4. MVP 우선순위

처음 구현할 때는 아래 5개만 넣어도 충분하다.

| 우선순위 | 이벤트 | 이유 |
|---:|---|---|
| 1 | `SponsorBoost` | 성공 보상이 바로 읽힌다. |
| 2 | `RecoveredPayload` | C 등급 재시도 동기가 생긴다. |
| 3 | `QuietLessons` | 비공개 실패의 역할이 선명하다. |
| 4 | `MediaBacklash` | 공개 실패 위험이 선명하다. |
| 5 | `FinalProof` | 최종 성공 연출에 필요하다. |

나머지는 수치 밸런스가 심심할 때 추가한다.

## 5. 저장 데이터 제안

새 시스템을 크게 만들 필요 없이, 결과 이벤트 인스턴스 하나와 다음 행동 보정 몇 개만 저장한다.

```text
LaunchOutcomeEventState
eventId
sourceMissionId
sourceGrade
createdYear
createdQuarter
pendingEntryCostDelta
pendingInstallCostDiscountPercent
pendingInstallCostDiscountCap
pendingPublicRewardMultiplierDelta
pendingWaitPenalty
targetEnginePresetId
completionDelta
statDeltaFuel
statDeltaCooling
statDeltaPower
statDeltaIgnition
pendingNoQuarterCostResearch
consumeOnMissionId
consumeOnNextAction
```

MVP에서는 모든 필드를 만들 필요 없다. 선택한 이벤트가 쓰는 값만 갖고 시작한다.

## 6. UI 표시

결과 보고서 하단에 작은 이벤트 카드 1개를 붙인다.

필수 표시:

- 이벤트 이름
- 한 줄 설명
- 실제 효과 수치

예:

```text
후원 기관 추가 지원
공개 발사 성공이 주목받았습니다.
효과: 즉시 연구비 +300, 분기 연구비 +50
```

다음 행동에 남는 돈/시간 효과는 연구 화면 상단 또는 발사 확인창에도 다시 보여준다. 숨은 보정으로 두지 않는다.

## 7. 제외할 것

이번 범위에서는 아래를 넣지 않는다.

| 제외 요소 | 이유 |
|---|---|
| 이벤트 선택지 2~3개 | UI와 밸런스가 커진다. |
| 장기 상태 이상 | 48시간 범위에서 추적 부담이 크다. |
| 성공률, 설계 평가, 위험도 보정 | 실제 물리 발사에서는 의미 없는 단위다. |
| 큰 폭의 엔진 스탯 상승 | 연구 행동의 역할과 충돌한다. |
| 랜덤 부품 파괴 | 현재 설계/부착 시스템과 비용 추적이 복잡해진다. |
| 발사 중 이벤트 개입 버튼 | `발사 중 플레이어 입력 금지` 원칙과 충돌한다. |
| 연쇄 이벤트 | 결과 원인이 흐려지고 디버깅이 어려워진다. |

## 8. 요약

발사 결과 이벤트는 성공/실패를 다시 굴리는 시스템이 아니다. 실제 발사 결과에 운영 의미를 붙이는 작은 보상/손실 장치다.

가장 중요한 구분은 세 가지다.

1. 공개 성공은 돈과 평판을 준다.
