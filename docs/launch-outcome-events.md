# 발사 결과 이벤트

실제 비행의 성공/실패가 확정된 뒤 운영 효과를 적용한다. 발사 판정과 물리는 바꾸지 않는다. 효과 단위는 돈, 시간, 엔진 완성도, 엔진 스탯뿐이다.

## 이벤트 10종

최종 미션을 제외한 발사를 일반 미션이라고 부른다. 종료 사유는 `LaunchTerminationReason`으로 전달하며 표시 문자열을 분석하지 않는다.

| ID / 이름 | 발생 조건 | 효과 |
|---|---|---|
| `SponsorBoost` 후원 기관 추가 지원 | 일반 미션 공개 성공 | 즉시 연구비 +500, 분기 연구비 +100 |
| `CleanTelemetry` 깨끗한 비행 데이터 | 일반 미션 성공 | 즉시 연구비 +100, 대상 엔진 완성도 +5, 최저 스탯 +4, 다음 일반 연구 시간 면제 |

| `PadDamage` 발사대 손상 | 일반 미션 공개 지면 추락 실패 | 즉시 연구비 -200, 다음 설계 진입 비용 +150, 사용 엔진 무작위 한 프리셋 완성도 -3 |

| `MediaBacklash` 공개 실패 역풍 | 일반 미션 공개 실패 | 분기 연구비 -150, 다음 공개 성공 이벤트 연구비 -25% |

| `FinalFailure` 최종 검증 실패 | `LowPowerZoneHold` 실패 또는 제한 시간 만료 | 특별호 기사 표시, 추가 운영 효과 없음 |

장비 회수는 이륙하지 못한 장비를 다시 사용한다는 내용으로 표시한다. 실패 분석은 수집하지 않는 사고 원인을 추정하지 않고 최저 스탯을 올린다. 최종 미션 실패는 즉시 게임을 끝내지 않고 남은 기간을 계속 진행한다. 제한 시간이 끝났는데 최종 미션을 통과하지 못했으면 `FinalFailure` 특별호를 표시한다.

## 선택과 정산

- 적합한 후보 중 동일 가중치로 하나를 선택한다. 다른 후보가 있으면 직전 이벤트를 제외한다. 후보가 없으면 적용하지 않는다.
- 이벤트 전용 난수는 캠페인 시드로 초기화한다. 연구 난수에 영향을 주지 않는다. 모델 생성자의 `eventRandom` 함수로 테스트 선택을 제어할 수 있다.
- 보상 대상은 설치 개수가 가장 많은 엔진 프리셋이다. 동률이면 프리셋 ID가 앞선 쪽을 선택한다. 설치 엔진이 없으면 엔진 효과와 연구 시간 혜택을 생략한다.
- 발사대 손상의 엔진은 사용한 서로 다른 프리셋 중 동일 확률로 고른다.
- 최저 스탯 동률 순서는 연료 탱크 용량, 냉각 능력, 최대 출력, 점화 신뢰도다.
- 일반 미션 공개/비공개 발사의 기본 보상/패널티는 0이며, 분기 진행 전에 이벤트를 적용한다. 변경된 분기 연구비가 해당 분기 수입에도 반영된다.
- 완성도와 스탯은 0~100, 연구비는 0 이상, 분기 연구비는 기존 설정 범위로 제한한다. 보고서에는 제한 후 실제 증감량을 표시한다.
- 결과 보고서와 이벤트 알림은 정산 결과만 읽는다. 다시 열거나 재발행해도 효과를 중복 적용하지 않는다.

## 남은 효과 소비

- 일정 압박은 다음 정상 처리 행동에서 끝난다. 대기, 일반/집중 연구, 새 엔진 개발, 설계 진입을 포함한다. 실패한 행동은 소비하지 않는다.
- 설계 진입 비용 보정은 진입 비용을 실제 지불할 때 소비한다. 이후 설계에서 돌아와도 이미 지불한 비용과 소비된 보정을 되돌리지 않는다. 지불 전 취소는 소비하지 않는다. 2026-09-05 밸런스 패치 이후 기본 진입 비용은 `50`이므로 할인·할증은 `50` 단위로 제한하고, 할인 후 최저 진입 비용은 `0`이다.
- 같은 미션 설치비 할인은 발사를 확정할 때 소비한다. 다른 미션, 설계 편집, 발사 취소, 예산 부족으로는 소비하지 않는다. 할인액은 정수 설치비의 20%를 버림한 값이며 최대 300이다.
- 공개 성공 이벤트 연구비 감소는 다음 발사 확정 때 귀속된다. 공개 발사는 성공 이벤트의 연구비와 분기 연구비 변동을 25% 줄이고, 비공개/최종 발사는 효과 없이 소비한다.
- 연구 시간 면제는 지정된 엔진의 다음 일반 연구에만 적용한다. 연구비는 정상 지불하며 시간과 분기 수입이 모두 발생하지 않는다. 다른 엔진 연구, 집중 연구, 실패한 연구 행동은 혜택을 유지한다.
- 같은 종류의 혜택은 중첩하지 않고 갱신한다. 새 시간 면제는 대상 엔진을, 새 설치비 할인은 대상 미션을 갱신한다. 서로 다른 종류는 함께 유지한다.
- 새 게임에서 모든 이벤트 상태와 전용 난수를 초기화한다. 기존 연구 세션 수명을 따르며 별도 디스크 저장 시스템은 추가하지 않는다.

## 코드와 UI

성공 연출용 프리팹과 후속 Timeline 연결 범위: [미션 성공 연출](mission-success-cinematic.md)

`ResearchLaunchEvents.cs`가 후보, 선택, 효과, 대기 상태와 비용 계산을 담당하고 `ResearchPrototypeModel`의 행동 처리에 연결된다. 실제 종료 사유는 평가기 → 미션 컨트롤러 → 스테이지 호스트 → 연구 세션 → 모델 순서로 전달한다.

신문 자체가 발사 후 이벤트 발표 화면이다. 기존 수치 보고서를 별도로 띄우지 않고, `ResearchResultReportController`가 `NewspaperReveal`에 기사와 사진을 전달한다. 신문에는 이벤트별 제목, 짧은 기사, 테스트 정산과 이벤트 효과의 실제 적용값을 표시한다. 공개 발사는 정규판, 비공개 발사는 연구소 내부 회보, 최종 성공과 최종 실패는 특별호다. 등장 연출이 끝난 뒤 신문을 누르면 연구 화면 또는 기존 엔딩으로 이동한다.

표시 매체는 테스트 공개성으로 결정한다. 공개 테스트와 최종 미션은 항상 신문이고 비공개 테스트는 항상 메일이다. 유일한 예외는 비공개 실패의 `Whistleblower`로, 은폐됐던 내용이 외부에 알려진 사건이므로 신문 특종으로 표시한다. 이벤트별 매체 강제 목록이나 다른 매체 스프라이트 폴백은 사용하지 않는다.

신문과 메일은 각각 `NewspaperReveal.prefab`, `MailReveal.prefab`으로 분리한다. 두 프리팹은 같은 등장·타이핑·닫기 동작을 공유하지만 배경 이미지, 텍스트 배치와 사진 재질은 각 프리팹에 고정된다. `ResearchResultReport.prefab`이 두 프리팹을 함께 참조하고 결과 매체에 맞는 하나만 활성화한다. 신문은 기존 저장 프리팹의 스프라이트, 배치, 사진 재질과 연출 설정을 그대로 유지한다. 스크립트는 원래 `newspaperSprite` 필드를 유지해 커밋 `6645f8df17731603451130b554b39c3c3a5caa81`의 `newspaper-original-transparent_0`를 직접 참조한다. 빌더는 신문 배치를 재작성하지 않는다.

메일 매체는 기사체를 쓰지 않는다. 제목은 `[시험 결과] {미션명} - {보고 항목}` 형식이다. 본문은 연구 책임자에게 보내는 내부 업무 메일로 작성한다. 첫 문장은 `책임자님,`으로 시작하고, 시험 결과 확인, 이벤트 전달 사항, 정산과 후속 조치 안내 순서로 구성한다. 효과 목록과 닫기 흐름은 신문과 같다. 메일 프리팹은 `Email.png`의 우측 메시지 패널에 제목, 발행 정보, 본문, 사진과 효과 목록을 배치하며 사진은 원본 컬러로 보여준다. 메일 제목은 원본 이미지 기준 상단 좌표 306px에 배치하고 줄바꿈 없이 한 줄로 표시한다. 긴 제목은 20~10pt 범위에서 자동 축소하며 텍스트 잘라내기는 사용하지 않는다. 메일 결과·정산 글씨는 불투명 검정색(#000000)으로 표시하고, 결과 배경 패널보다 뒤쪽 형제 순서에 배치해 패널이 글씨를 덮지 않게 한다.

`newspaper-original-transparent.png`의 빈 제목과 기사 영역에 내용을 배치한다. 사진은 기사칸 왼쪽 약 60%, 본문은 오른쪽에 두고, 실제 후속 조치는 하단 영역에 표시한다. 모든 내용은 신문 종이와 함께 회전한다. 발사 전 결과 예측은 표시하지 않는다.

### 신문 공개 순서

표시물의 동적 내용은 착지 후 순서대로 공개한다. 회전하며 날아오는 동안 제목·발행 정보·사진·본문·결과를 숨긴다. 착지 후 발행 정보와 제목 타이핑(기본 글자당 0.055초), 사진 즉시 표시와 본문 타이핑(0.012초), 결과 항목별 표시(0.3초)를 진행한다. 단계 사이 간격은 기본 0.15초다. TextMeshPro의 표시 글자 수로 제어해 전체 문장의 줄바꿈과 크기를 유지하며, 결과 항목이 화면에서 줄바꿈되더라도 해당 항목 전체를 함께 표시한다. 메일도 같은 순차 공개 효과를 사용한다. 모든 출력이 끝나야 닫을 수 있고, 중단·재표시 시 진행 상태를 초기화한다.

완성도는 100에서 추가 연구가 막히므로, 상승할수록 남은 연구 여지를 소모하는 수치다. 출력 연출은 완성도 증가를 무조건 긍정 효과로 강조하지 않으며 이벤트 수치를 변경하지 않는다.

### 발사 현장 사진

- `LaunchPhotoCapture`가 별도 카메라와 RenderTexture로 1024x768 사진 한 장을 만든다. 우주선의 크기와 비행 카메라 방향으로 구도를 잡고 UI와 편집용 선을 촬영에서 제외한다. 화면 전체 스크린샷이나 추락 프레임 버퍼는 사용하지 않는다.
- 원본 사진은 컬러로 유지하고, 신문의 RawImage에는 `Border/UI/NewspaperPhoto` 머티리얼을 적용한다. 명암을 짙은 잉크색과 누르스름한 종이색 사이로 변환해 신문과 같은 인쇄 톤으로 표시한다.
- 사진에는 4x4 Bayer 디더링을 적용한다. 기본값은 강도 0.8, 원본 사진 기준 셀 크기 4픽셀, 명암 4단계다. 무늬를 사진 UV에 고정해 신문이 움직여도 점이 화면 위에서 미끄러지지 않는다. 머티리얼에서 강도·셀 크기·명암 단계를 조절할 수 있다.
- 성공·일반 실패는 판정 확정 뒤 우주선 정지 전에 촬영한다. 자폭·과열 폭발은 `Rocket.ExplosionPhotoRequested`를 사용한다. 폭발 효과가 없으면 렌더러를 숨기기 전에, 효과가 있으면 생성 후 다음 프레임에 촬영한다.
- 촬영 중에는 시뮬레이션 씬 해제를 기다린다. 촬영 실패 시 신문에 `현장 사진 수신 실패`를 표시하며 보상 정산은 그대로 진행한다.
- 사진은 연구 세션이 소유한다. 신문 확인, 새 발사, 새 게임, 세션 종료 시 해제하며, 세대 번호가 지난 촬영 결과는 폐기한다. 디스크 저장과 외부 생성형 API는 사용하지 않는다.
- 발사 종료 직후에는 결과를 확인 처리하지 않는다. 성공·실패 연출과 발사 정보 패널의 대기 시간이 끝나면 `SimulationTest` 씬을 유지한 채 그 위에 신문 또는 메일과 반투명 검정 배경을 표시한다. 플레이어가 결과 UI를 닫을 때만 결과 확인과 사진 해제를 수행하고, 이어서 시뮬레이션 씬을 내린 뒤 연구 화면 또는 엔딩으로 전환한다. 바다 추락을 포함한 모든 종료 사유에 같은 규칙을 적용한다.
- 기존 독립 신문 미리보기 오브젝트는 비활성으로 보관한다. 실제 발표는 결과 어댑터에 연결된 신문 한 곳에서만 처리한다.

연구 화면과 설계 확인 화면에는 남은 효과를 다시 표시한다. 비용 표시와 실제 결제는 같은 모델 계산을 사용한다.

## 검증 범위
