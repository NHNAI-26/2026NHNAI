# 연구 단계 개발 계획

> 개정일: 2026-09-06
>
> 기준: 실제 물리 발사 구조

## 1. 범위

연구 단계는 `01_Main.unity` 안에서 캠페인 운영, 엔진 프리셋 개발, 미션 선택과 설계 진입을 담당한다. 실제 조립과 발사는 각각 설계 화면과 시뮬레이션 화면이 담당한다.

## 2. 엔진 프리셋

```text
presetId
unlocked
completion
fuelCapacity
cooling
maxOutput
ignitionReliability
```

- 프리셋은 최대 10개다.
- 시작 시 엔진 01만 열린다.
- 새 엔진 개발로 다음 프리셋을 순서대로 연다.
- 완성도는 네 스탯이 공유하는 연구 가능량이다.
- 완성도 100에서는 추가 연구를 막는다.
- 연구는 선택한 프리셋과 스탯만 바꾼다.

## 3. 운영 화면

허브에는 날짜와 남은 분기, 보유 연구비, 분기 연구비를 표시한다. 주요 행동은 `부품 개발`, `로켓 설계`, `건너뛰기`다.

부품 개발 패널에는 아래 요소를 둔다.

- 개발된 엔진 프리셋 목록
- 새 엔진 개발
- 선택 엔진의 완성도
- 네 스탯의 수치와 게이지
- 기본·집중 연구 모드
- 개발 시작

개발 시작과 연구실 복귀 버튼은 프리팹의 `168×52` 크기를 사용한다. 부모 레이아웃이
자식 크기를 제어하지 않으므로, `01_Main` 씬에서 두 버튼의 `m_SizeDelta`를 `0×0`으로
덮어쓰지 않는다. 버튼이 사라지거나 클릭되지 않으면 이 크기 오버라이드를 먼저 확인한다.

미션 결과는 별도 결과 매체가 담당한다. 운영 화면에 과거 결과 요약이나 결과 예측을 중복 표시하지 않는다.

## 4. 연구 미니게임

- 연료: 게이지 입력값으로 점수를 확정한다. 안내 문구는 “최대게이지까지 채우세요”다. 입력 대기 중 계기판 버튼은 0.9초 주기로 초록색 밝기가 변하며, 누르는 동안 밝은 초록색을 유지한다. 게이지가 차는 동안 `Gauge` 효과음을 반복 재생하고, 최대치 도달·손 떼기·판정·화면 종료 시 멈춘다. 다음 시도에서는 점멸을 다시 시작한다.
- 냉각: 밸브 조작으로 열을 관리한다.
- 출력: 움직이는 커서를 목표 영역에서 고정한다.
- 점화: 2개→3개→4개 순서를 기억해 입력한다. 시작 후 0.5초 동안 소등 상태로 기다리고, 각 정답을 0.45초씩 보여준다. 시연이 끝나면 모든 버튼을 끈 상태로 0.5초 기다린 뒤 전체 점등하여 입력을 받는다.

점화의 정답 입력은 `button8`(`freesound_community-button-8-88355.mp3`)을 한 번 재생하고 전체 소등한다. 0.125초 펀치가 끝나면 남은 순서 입력을 위해 다시 점등하며, 라운드의 마지막 정답이면 다음 순서 시연으로 넘어간다. 오답은 `wrong`(`wrong.mp3`)을 한 번 재생하고 전체 버튼을 0.1초 간격으로 3회 깜빡인 뒤 다음 라운드로 넘어간다. 시연·소등·판정 중에는 추가 입력과 기본 클릭음을 받지 않는다. 입력 대기 시간만 반응 속도 점수에 포함한다. 펀치는 누른 버튼만 94%→106%→98%→114%→100%로 움직이며, 숨김·비활성화·재사용·결과 진입 시 원래 크기로 복원하고 사운드와 파티클을 정리한다.

정답 클릭 파티클은 BreakShoot 프로젝트의 `Assets/Effects/SlotMachine/ButtonClick.vfx`를 ParticleSystem으로 이식했다. 원본 `ButtonEffect.psd`의 2×2 이미지와 `circle.png`를 `Assets/05. Arts/VFX/Resources/Ignition/`에 복사해 사용한다. 두 레이어의 0.1초 방출, 150/300 방출률, 0.3~0.6초/0.4~0.8초 수명과 알파 곡선을 유지하고 크기·속도는 UI 좌표에 맞췄다. `IgnitionClickParticles`가 ParticleSystem의 입자를 Canvas 메시로 표시하므로 Overlay Canvas에서도 가려지지 않는다. 정답 시연과 오답에서는 파티클을 재생하지 않는다.

모든 미니게임은 최종 점수가 50점 이상인 성공·훌륭한 개발 결과에서 `success.mp3`를 `success` ID로 한 번 재생한다. 50점 미만과 냉각 과열 게임오버에서는 재생하지 않는다. 결과 닫기·숨김·비활성화·재사용·파괴 시 성공음 핸들을 정리한다.

점수는 선택 스탯의 증가량을 정한다. 연구 행동을 다시 성공·실패로 나누지 않는다. 결과 닫기 시 성장 적용 콜백을 한 번만 실행한다.

최대 출력은 버튼이나 출력 영역을 누르는 순간 화면에 표시된 커서 위치를 확정한다. 판정 중에는 커서와 제한 시간을 고정하고 추가 입력을 받지 않는다. 손을 뗄 때는 다시 판정하지 않는다.

입력 펀치는 게이지(`OutputTrack`)에만 적용하여 자식인 목표 구간·정밀 목표·커서가 같은 중심과 박자로 움직인다. 배경·버튼·판정 글자·바깥 패널은 움직이지 않는다. 입력 직후 94%로 눌리고 0.045초 안에 106%까지 짧게 반동한다. 성공하면 이어서 0.025초 동안 Great는 111%, Perfect는 114%까지 확장하고, 0.055초 동안 원래 크기로 부드럽게 복귀한다. 중간 대기와 정점 정지를 없애고 진폭을 키워 전체 성공 펀치를 0.125초로 짧게 만든다. 판정 글자는 별도로 튀지 않으며 게임 전체 시간은 건드리지 않는다. Miss는 게이지와 그 자식들만 좌우로 0.27초 동안 흔들며 진폭을 줄인다. 시간 초과는 입력 펀치 없이 Miss 흔들림만 재생한다. 다음 단계, 결과 화면, 재사용 또는 비활성화 시 연출을 종료하고 원래 위치와 크기로 복원한다.

출력 UI의 배경·트랙·목표·정밀 목표·커서는 `Shader/Uber/UI` 홀로그램 머테리얼을 사용한다. 어두운 청록 배경과 느린 스캔라인 위에 초록 목표, 금색 정밀 목표, 청백색 커서를 구분한다. `Resources/ResearchUI/OutputHologram_*.mat`에 설정을 저장하고 프리팹과 런타임에 함께 적용하여 씬에 미리 배치한 UI도 같은 스타일을 사용한다. 스프라이트 아틀라스 좌표는 `UberUIMaterialBinder`가 전달한다.

게이지 이동 중에는 `Gauge.wav`를 `Gauge` ID로 반복 재생한다. 입력 또는 시간 초과 판정 순간 루프를 즉시 정지하고 Great·Perfect는 `hit.mp3`(`hit`), Miss·시간 초과는 `wrong.mp3`(`miss`)를 한 번 재생한다. 다음 단계에서 루프를 다시 시작하며, 숨김·비활성화·파괴·게임 전환·결과 진입 시 이 미니게임이 재생한 사운드 핸들만 정리한다. 효과음은 기존 SoundManager의 2D SFX 경로를 사용한다.

냉각은 열이 기본 70% 이상이면 `warning`을 반복 재생하고 60% 이하로 식으면 종료한다. 경고 기준은 컨트롤러의 `coolingWarningThreshold`에서 조정하며 해제 기준은 그보다 10%p 낮다. 실제 밸브 회전이 발생할 때만 `stone push`와 파이프 이미지의 미세 진동을 재생한다. 시계 방향으로 여는 동안에는 `steam`도 반복 재생하며 반대 방향으로 닫으면 증기 소리는 멈춘다. 입력 판정에 영향을 주지 않도록 밸브 자체와 주변 UI는 흔들지 않는다. 회전 입력이 0.12초간 없으면 진동과 회전·증기 소리를 멈추고 파이프 위치를 복원한다. 손을 떼거나 중앙 무반응 영역으로 들어가면 즉시 멈추며, 숨김·비활성화·파괴·게임 전환·결과 진입 시 경고음까지 정리한다.

## 5. 미션 상태

```text
missionId
unlocked
completed
attemptCount
```

시작 시 첫 미션만 열린다. 실제 발사에서 미션 조건을 처음 충족하면 완료 상태를 기록하고 다음 미션을 연다. 마지막 미션을 완료하면 승리한다.

## 6. 설계 진입

1. 열린 미션을 선택한다.
2. 설계 진입 비용을 확인한다.
3. 일반 미션은 공개·비공개를 고른다.
4. 비용을 한 번 차감하고 설계 화면을 연다.
5. 취소하면 설치 예약만 버리고 운영 화면으로 돌아온다.

공개 여부는 결과 매체와 후속 이벤트에만 전달한다.

## 7. 발사 결과 수신

연구 세션은 시뮬레이션에서 아래 결과만 받는다.

```text
runId
missionId
succeeded
terminationReason
telemetry
visibility
usedEnginePresetIds
```

세션은 같은 `runId`를 두 번 적용하지 않는다. 성공 시 진행 상태를 갱신하고, 후속 이벤트를 한 번 정산한 뒤 결과 매체를 표시한다.

## 8. 종료 처리

- 최종 미션 성공은 같은 분기 안에서 기간 만료보다 우선한다.
- 남은 분기가 없고 최종 미션을 완료하지 못했으면 실패 특별호 뒤 패배 화면으로 이동한다.
- 종료 뒤에는 추가 행동과 중복 정산을 막는다.
- 새 게임은 날짜, 자금, 엔진, 미션, 대기 결과와 실행 ID를 초기화한다.

## 9. 검증

- 연구는 선택 프리셋과 선택 스탯에만 적용된다.
- 완성도와 스탯은 0~100을 벗어나지 않는다.
- 새 엔진은 10개를 넘지 않는다.
- 설계 진입 비용과 설치 비용이 중복 차감되지 않는다.
- 실제 미션 성공만 다음 미션을 연다.
- 결과 재표시와 버튼 연타가 성장, 비용, 해금과 이벤트를 반복하지 않는다.
- 공개 여부를 바꿔도 발사 물리와 미션 평가가 바뀌지 않는다.

## 10. 남은 구현 정리

현재 런타임에 과거 결과 모델을 위한 호환 필드와 이벤트 분기가 남아 있다. 새 기능은 여기에 의존하지 않는다. 호출부, UnityEvent와 직렬화 참조를 확인한 뒤 코드 정리 작업에서 성공/실패 이벤트와 실제 텔레메트리 모델로 축소한다.
