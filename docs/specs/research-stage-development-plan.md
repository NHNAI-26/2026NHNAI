## 1. 핵심 변경

기존 단계별 진행도 모델은 폐기한다. `Engine/Rocket/Orbit/Moon`은 연구 항목이 아니다.

연구 단계에서 플레이어가 직접 성장시키는 대상은 `Engine01`~`Engine10` 엔진 프리셋이다. 10개 프리셋은 모두 같은 초기 스펙, 같은 일반 연구 비용, 같은 집중 연구 비용, 같은 설치 비용을 가진다. 차이는 플레이어가 어떤 프리셋을 얼마나 연구했는지에 따라 게임 세션 중에만 생긴다.

날씨, 환경 예보, 발사창 보정은 만들지 않는다.

## 2. 연구 단계 범위

연구 화면은 프로젝트 운영 화면이다.

담당 기능:

- 날짜, 남은 분기, 연구비, 분기 연구비 표시
- 엔진 프리셋 10개 상태 표시
- 연구할 엔진 프리셋 선택
- 연구할 스탯 선택
- 일반 연구와 집중 연구 실행
- 엔진 테스트, 로켓 테스트, 궤도 테스트, 달 착륙 진입 조건 표시
- 설계 진입 버튼 제공
- 1분기 대기 제공

담당하지 않는 기능:

- 로켓·궤도·달 연구
- 발사 결과 미리 굴림
- 발사 비용 선차감
- 설계 조작의 정식 구현
- 3D 발사 연출의 정식 구현
- 날씨, 환경 예보, 발사창 보정

## 3. 도메인 모델

### EnginePresetState

각 엔진 프리셋은 아래 상태를 가진다.

```text
presetId
level
fuelCapacity
cooling
maxOutput
ignitionReliability
attemptCount
bestGrade
```

규칙:

- 프리셋 수는 10개 고정
- 최대 레벨은 5
- 초기 스탯과 비용은 10개 모두 동일
- 일반 연구는 선택 프리셋 레벨 +1
- 집중 연구는 선택 프리셋 레벨 +2
- 연구는 선택한 프리셋과 선택한 스탯에만 적용
- 발사 결과는 엔진 레벨이나 스탯을 직접 올리지 않음

### StageState

`Engine`, `Rocket`, `Orbit`, `Moon`은 발사 단계다.

```text
stageId
unlocked
attemptCount
bestGrade
```

로켓, 궤도, 달에는 연구 진행도와 연구 버튼이 없다.

## 4. 단계 해금

| 단계 | 설계 진입 조건 |
| --- | --- |
| 엔진 테스트 | 선택 엔진 프리셋 레벨 1 이상, 발사 비용 600 보유 |
| 로켓 테스트 | 로켓 단계 해금, 발사 비용 900 보유 |
| 궤도 테스트 | 궤도 단계 해금, 발사 비용 1200 보유 |
| 달 착륙 | 달 단계 해금, 발사 비용 1800 보유 |

| 해금 | 조건 |
| --- | --- |
| Rocket | 어떤 엔진 프리셋이든 엔진 테스트 C 이상 |
| Orbit | Rocket 테스트 C 이상 |
| Moon | Orbit 테스트 C 이상 |

`C 이상`은 S/A/B/C다. F는 다음 단계 해금으로 인정하지 않는다.

## 5. 화면 흐름

모든 흐름은 `01_Main.unity` 안에서 화면만 바꾼다.

```text
연구 화면
→ 설계 진입
→ 설계 화면
→ 발사
→ 발사 결과 화면
→ 연구 화면 또는 승리/패배 화면
```

설계 진입은 비용, 분기, 발사 횟수, 결과를 소비하지 않는다. 설계 화면에서 연구 단계로 돌아가면 pending 설계 데이터만 버린다.

발사 버튼을 누른 뒤에만 발사 비용과 예약된 엔진 설치 비용을 확정 차감하고 결과를 한 번만 굴린다.

## 6. 구현 단계

### Phase 1. 엔진 프리셋 연구 모델

- `EnginePresetId`, `EngineStatId`, `TestVisibility` 정의
- 엔진 프리셋 10개 상태 생성
- 일반/집중 연구 구현
- 점수 입력에 따른 선택 스탯 증가 구현
- 레벨 5 상한 처리
- 로켓·궤도·달 연구 버튼 제거

### Phase 2. 연구 운영 UI

- 엔진 프리셋 10개 카드 표시
- 선택 엔진 상세 스탯 표시
- 낮음/보통/높음 임시 점수 입력 제공
- 일반 연구, 집중 연구, 설계 진입, 대기 버튼 연결
- 잠긴 발사 단계 조건 표시
- 날씨/환경/예보 문구 제거

### Phase 3. 설계 진입 경계

- `ResearchDesignEntryData` 생성
- `ResearchFlowSession`에서 모델과 pending 설계 데이터 보존
- 설계 진입 성공 시 연구 화면 숨김
- 같은 씬 안에서 설계 화면 표시
- 연구 단계 복귀 시 pending 설계 데이터만 삭제

### Phase 4. 임시 설계 화면

- 설치할 엔진 프리셋 선택
- 엔진 설치 개수와 예약 비용 표시
- 설계 적합도 임시 조절
- 공개/비공개 테스트 선택
- 달 착륙은 `FINAL MISSION` 표시
- 실제 설계 조작은 별도 담당이 교체 가능하게 느슨하게 유지

### Phase 5. 발사 확정과 결과

- 발사 버튼에서만 비용 확정 차감
- 설치 엔진 성능, 직전 단계 최고 등급, 발사 경험, 설계 적합도, 공개성 보정으로 성공률 계산
- 발사 결과는 한 번만 고정
- 결과 보상과 분기 연구비 변화를 한 번만 적용
- C 이상이면 다음 단계 해금
- Moon B 이상이면 승리

## 7. 테스트 기준

- 일반 연구는 선택 엔진만 레벨 +1, 선택 스탯 증가
- 집중 연구는 선택 엔진만 레벨 +2, 선택 스탯 증가
- 레벨은 5를 넘지 않음
- 10개 엔진 프리셋은 같은 초기 스탯과 비용
- 로켓/궤도/달에는 연구 진행도 없음
- 설계 진입은 비용/분기/발사 횟수/진행도 미소비
- 발사 확정만 비용/분기/발사 횟수/보상/손실 적용
- 결과 재표시와 버튼 연타로 보상 중복 없음
- 날씨/환경 예보/발사창 보정 상태 없음

## 8. 현재 구현 메모

현재 임시 구현은 실제 설계 담당자가 막히지 않도록 설계 화면을 단순 UI로 둔다. 진짜 설계 조작, 로켓 배치, 3D 연출은 별도 담당자가 교체할 수 있다.

추천 구현 원칙:

- 모델은 순수 C#에 가깝게 유지
- UI는 `ResearchPrototypeModel`과 `ResearchFlowSession`을 읽고 쓰는 얇은 레이어로 유지
- 설계 화면은 pending 데이터를 수정하고 발사 확정만 모델에 위임
- 결과 적용은 반드시 한 번만 수행
