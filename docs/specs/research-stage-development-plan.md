## 1. 핵심 변경

연구→설계→물리 발사 연결에서 점화 신뢰도는 연구 수치를 그대로 확률(%)로 사용한다. 연구 40은 40%, 66은 66%이며 0~100%로 제한한다. 슬롯의 기본 점화 확률은 연구 엔진 확률에 곱하지 않는다. 연료·냉각·출력은 기존 기본 프리셋 × 연구 수치 / 40 변환을 유지하며 원본 에셋은 수정하지 않는다. 기존 연구 수치 40도 실제 40%가 되므로 이전의 100% 점화보다 실패가 늘어난다.

점화 판정은 발사 시작 시 한 번만 수행한다. 비행 중 재점화와 ON/OFF 조작은 미구현이며 이번 수정 범위에서 제외한다. 연구 설명도 초기 점화 성공률 향상만 안내한다.

기존 단계별 진행도 모델은 폐기한다. `Engine/Rocket/Orbit/Moon` 4단계 구조는 연구 항목도 정식 발사 미션도 아니다.

연구 단계에서 플레이어가 직접 성장시키는 대상은 개발된 엔진 프리셋이다. 프리셋 슬롯은 `Engine01`~`Engine10` 최대 10개지만, 게임 시작 시에는 `Engine01` 하나만 보인다. `새로운 엔진 개발` 버튼을 누르면 `Engine02`부터 순서대로 새 프리셋이 생긴다. 10개 프리셋은 모두 같은 초기 스펙, 같은 일반 연구 비용, 같은 집중 연구 비용, 같은 설치 비용을 가진다. 차이는 플레이어가 어떤 프리셋을 얼마나 연구했는지에 따라 게임 세션 중에만 생긴다.

엔진 레벨 시스템은 사용하지 않는다. 각 엔진 프리셋은 네 스탯이 공유하는 `완성도`를 가진다. 완성도는 연구 미니게임의 성공 정도와 무관하게 연구 행동 1회마다 `+10` 증가한다. 완성도 100에 도달한 엔진 프리셋은 연료량, 냉각, 최대 출력, 점화 신뢰도 중 어느 스탯도 더 개발할 수 없다.

현재 발사 구현의 미션은 `LowAltitude`, `HighAltitude`, `TargetZone`, `ZoneHold`, `LowPowerZoneHold` 다섯 개다. 정적 연소 슬롯은 기존 데이터 호환용 식별자만 남으며 첫 미션은 낮은 고도 도달이다.

날씨, 환경 예보, 발사창 보정은 만들지 않는다.

정식 UI는 동적 생성이 아니라 프리팹 기반으로 만든다. 코드 생성기는 에디터 재생성 도구로만 둔다. 설정창은 `SettingsMenu.prefab`, 일시정지창은 `PauseMenu.prefab`이며 타이틀/메인 씬에 미리 연결한다. 런타임에는 기존 오브젝트를 표시하거나 숨긴다.

연구 화면과 엔진 카드에는 `fae80a1`의 `engine_ui_01.psd` 스프라이트를 사용한다. `_0`은 외곽 패널, `_1`/`_2`는 완성도 게이지의 채움/바탕, `_3`은 엔진 아이콘, `_4`는 스탯 선택 버튼, `_5`는 연구·설계 행동 버튼, `_6`은 엔진 카드와 보조 버튼에 연결한다. 원본의 슬라이스와 테두리 값을 유지하고 프리팹에 직접 저장한다. 기존 프리팹은 `Border/Research/Apply Engine UI Art` 명령으로 배치를 재생성하지 않고 아트만 다시 적용할 수 있다. UI 재생성 도구도 같은 아트 적용 경로를 사용한다.

`SelectedEngineCompletion`은 조작 불가 게이지이며 선택 엔진의 기존 완성도 0~100을 표시한다. 카드 선택이나 연구 완료 시 기존 텍스트와 함께 갱신한다. 중앙 전시 영역에는 새 UI 그래픽을 추가하지 않는다.

설계 진입은 `ResearchTestVisibilityDialog.prefab`에서 공개/비공개를 선택한 뒤 확정한다. 기본은 비공개이며 선택창 열기·취소는 비용과 분기를 소모하지 않는다. 최종 미션은 선택창을 생략한다. 선택은 `ResearchDesignEntryData.Visibility`에 고정하고 임시 설계 화면의 공개성 변경 버튼은 제거한다. 현재 물리 버전에서 공개성은 경제 효과만 적용하며 성공률과 점화 확률을 바꾸지 않는다.

`ResearchLaunchOutcome.asset`은 결과 데이터와 사유를 전달하는 이벤트 채널이다. 세션이 보상과 결과를 확정한 뒤 통지를 대기시키고, 물리 발사 씬 정리 및 연구/엔딩 복귀 완료 후 `PublishPendingLaunchOutcome()`을 한 번 호출한다. 임시 경로는 보고서 표시 후 통지한다. 보고서 확인 여부와 통지 대기는 별개이며 새 게임에서는 대기 통지를 지운다.

메인 씬의 `ResearchLaunchOutcomeHooks` 프리팹에서 `Succeeded`(S/A/B), `Partially Succeeded`(C), `Failed`(F) UnityEvent에 후속 UI·음향·연출을 연결한다. 코드에서는 채널의 `OnEventRaised` 또는 리스너의 `LastOutcome`으로 미션·공개성·등급·보상·최종 승패·사유를 읽는다. 기본 리스너는 연결 항목이 비어 있어 별도 팝업을 자동 표시하지 않는다. `Border/Research/Rebuild Test Visibility Dialog`와 `Border/Research/Install Test Visibility and Outcome Hooks` 명령으로 프리팹 생성과 씬 연결을 갱신한다.

미니게임은 스탯별 전용 아트를 사용한다. 냉각은 `pipe-64xpipe`와 `Velve`, 연료는 `gage`·`gage_stick`·`gauge-hub`, 출력은 `Power_Back`·`Power_Gage`·`Power_Target`·`Power_Cursor`를 연결한다. 기존 프리팹 생성기와 아트 적용기를 함께 갱신하며 Unity Editor API로 미니게임 프리팹을 저장한다. 메인 씬의 기존 인스턴스 반영을 확인하고 다른 연구 화면은 재생성하지 않는다. 표시와 판정은 PNG 투명 여백을 제외한 실제 트랙 영역을 기준으로 맞춘다.

결과 보고서와 엔딩도 `ResearchResultReport.prefab`, `ResearchEnding.prefab`을 `01_Main`의 독립된 비활성 인스턴스로 배치한다. 연구 컨트롤러는 직렬화된 화면 참조를 사용하며 런타임에 UI 오브젝트를 조립하지 않는다. 프리팹 재생성은 `Border/Research/Rebuild Result and Ending Prefabs`, 씬 연결은 `Border/Research/Install Session and Result Screens` 에디터 명령으로 수행한다.

`ResearchFlowSession`은 메인 씬의 독립 오브젝트로 두고 `ResearchBalanceConfig.asset`을 연결한다. 최초 세션 생성과 `ResetResearch()`에서 SO를 읽어 새 모델을 만든다. 실행 중 SO를 바꿔도 진행 중 모델에는 자동 반영하지 않는다. 타이틀의 게임 시작은 `PrepareNewGame()`으로 기존 세션만 초기화하고, 세션이 없으면 메인 씬이 생성하도록 둔다. 다시 시작은 날짜, 자금, 엔진, 미션, 발사 상태와 이전 결과를 지우고 엔진 01/연료 스탯을 선택한다.

연구 완료, 대기, 발사 확정은 같은 종료 판정을 거친다. 마지막 미션 B 이상이면 승리하며 마지막 분기 승리도 패배보다 우선한다. 그 외 남은 분기가 0이면 패배다. `FinalYear`/`FinalQuarter`는 마지막으로 소비한 분기를 저장한다. 종료 뒤에는 추가 행동과 중복 보상을 허용하지 않는다.

연구는 미니게임 결과 확인 후, 대기는 즉시 엔딩으로 이동한다. 발사는 `HasUnacknowledgedLaunchResult`가 켜진 동안 보고서를 먼저 표시하고, 확인 시 `AcknowledgeLaunchResult()`로 소비한 뒤 연구 또는 엔딩으로 이동한다. 실제 발사 씬에서 돌아오는 경로도 같은 규칙을 사용한다. 보고서 확인과 다시 시작 콜백은 표시 1회당 한 번만 실행된다.

마무리 검증 상태: 전체 솔루션과 연구 EditMode 테스트 어셈블리는 컴파일 오류 없이 빌드했다. 회귀 테스트 코드는 추가했으나 실제 Unity 테스트 실행 및 1280x720/1920x1080 Game View 검증은 사용자 요청으로 보류했다. 씬의 SO/결과 화면 참조는 저장돼 있다. 다음 검증 시 `ResearchCompletionFlowTests`와 기존 연구 테스트부터 실행한다.

냉각·연료·출력의 현행 조작과 점수 규칙은 아래 구현 메모를 따른다. 연료/출력 판정 연출은 TMP 알파와 크기를 DOTween으로 조정하며 CanvasGroup을 요구하지 않는다. 최종 결과는 2초 표시하거나 클릭으로 닫고, 닫힐 때 `ExecuteEngineResearch(...)`를 한 번 호출한다. 과열·미입력의 0점도 기존 연구 비용과 보상 규칙으로 완료한다.

연구 운영 화면은 허브와 부품 개발 패널 두 상태를 한 프리팹 안에서 전환한다. 허브는 제목, 정보 칩 3개, 하단 중앙 행동 버튼 3개(`부품 개발`, `로켓 설계`, `건너뛰기`)만 보여준다. 각 버튼은 자기 비용을 라벨에 달고 자금이 모자라면 비활성으로 어두워진다. `부품 개발` 버튼은 최소 비용인 기본 연구비를 `350~` 형태로 표시하고 그 금액을 못 내면 비활성이다. `부품 개발`을 누르면 허브 버튼이 사라지고 좌측 엔진 프리셋 열과 우측 상세 열이 슬라이드로 들어온다. 패널은 ESC로만 닫으며 별도의 닫기 버튼은 두지 않는다. ESC 한 번은 패널만 닫고 일시정지 메뉴를 열지 않는다 — `PauseMenuController`가 `ResearchOperationUIController.IsPartDevelopmentOpen` 동안 물러나고, 컨트롤러는 `LateUpdate`에서 ESC를 읽어 모든 `Update`보다 늦게 처리한다. 실행 순서 에셋은 쓰지 않는다.

`기본 연구`와 `집중 연구` 버튼은 실행 버튼이 아니라 모드 선택이다. 선택된 쪽만 밝게 표시하고, 우하단 `개발 시작` 버튼만 미니게임을 연다. 감당할 수 없는 집중 연구 모드에 갇히지 않도록, 자금이 집중 연구비 아래로 떨어지면 모드는 기본으로 되돌아간다. 미니게임을 마치면 허브가 아니라 부품 개발 패널로 복귀한다.

선택 엔진의 완성도 게이지 아래에 네 스탯(연료량, 냉각, 최대 출력, 점화 신뢰도)마다 이름·수치 라벨과 0~100 게이지를 한 줄씩 둔다. 게이지는 완성도 게이지와 같은 `AddGauge` 경로로 아트 적용기가 만들며, 없으면 라벨만 표시되고 화면 빌드는 실패하지 않는다.

`미션 결과 요약`과 `상태` 패널은 연구 화면에서 제거한다. 발사 결과는 결과 보고서 화면이 담당하며 `model.LastMessage`는 이 화면에 표시하지 않는다. 상단 칩은 날짜, 보유 자금, 분기 예산 3개이며 남은 분기는 날짜 칩에 `2018 Q1 · 남은 34분기`로 병기한다.

`docs/artemis-2026-gdd/11_UI_UX_화면설계.md`의 와이어프레임은 아직 옛 단일 화면(`[일반 연구] [집중 연구] [설계 진입] / [1분기 대기]` 한 줄)을 그리고 있다. 그 문서는 `확정` 상태라 이번 변경으로 수정하지 않았으므로, GDD 개정 여부는 별도 결정이 필요하다.

## 2. 연구 단계 범위

연구 화면은 프로젝트 운영 화면이다.

담당 기능:

- 상단 칩 3개로 날짜(남은 분기 병기), 보유 자금, 분기 예산 표시
- 허브 하단 행동 버튼 3개(`부품 개발`, `로켓 설계`, `건너뛰기`)와 각 비용 표시
- 개발된 엔진 프리셋 상태 표시
- 새로운 엔진 개발 버튼 제공
- 연구할 엔진 프리셋 선택
- 연구할 스탯 선택과 스탯별 완성도 게이지 표시
- 기본 연구와 집중 연구 모드 선택, `개발 시작`으로 실행
- 현재 미션, 해금 조건, 최고 등급, 시도, 경험 보너스, 진입 비용 및 주요 위험 정보란은 연구 화면에서 표시하지 않음
- 미션 결과 요약과 상태 메시지는 연구 화면에서 표시하지 않음

담당하지 않는 기능:

- 로켓·궤도·달 연구
- 연구 단계 4개 구조
- 발사 결과 미리 굴림
- 발사 결과 미리 굴림
- 설계 조작의 정식 구현
- 3D 발사 연출의 정식 구현
- 날씨, 환경 예보, 발사창 보정

## 3. 도메인 모델

### EnginePresetState

각 엔진 프리셋은 아래 상태를 가진다.

```text
presetId
completion
fuelCapacity
cooling
maxOutput
ignitionReliability
attemptCount
bestGrade
```

규칙:

- 프리셋 수는 10개 고정
- 완성도 범위는 `0~100`
- 완성도 100에 도달하면 해당 프리셋의 모든 연구 행동 비활성화
- 최대 10개 프리셋의 초기 스탯과 비용은 모두 동일
- 시작 시 개발된 프리셋은 1개
- 새 엔진 개발로 최대 10개까지 순서대로 추가
- 일반 연구와 집중 연구는 선택 프리셋 완성도를 `+10` 증가
- 집중 연구는 일반 연구보다 비용이 높고 선택 스탯 증가량이 큼
- 연구는 선택한 프리셋과 선택한 스탯에만 적용
- 발사 결과는 엔진 완성도나 스탯을 직접 올리지 않음

### LaunchMissionState

발사 미션은 연구 단계가 아니며, 미션별 해금과 결과 기록만 가진다.

```text
missionId
unlocked
attemptCount
bestGrade
```

발사 미션에는 연구 진행도와 연구 버튼이 없다.

## 4. 단계 해금

## 5. 화면 흐름

모든 흐름은 `01_Main.unity` 안에서 화면만 바꾼다.

```text
연구 화면
→ 설계 진입
→ 설계 화면
→ 발사
→ 발사 결과 화면
→ 연구 화면 또는 승리/패배 화면
```

설계 진입은 예산을 즉시 차감하지만 분기, 발사 횟수, 결과를 소비하지 않는다. 설계 화면에서 연구 단계로 돌아가면 pending 설계 데이터와 예약 설치 비용만 버린다.

발사 버튼을 누른 뒤에는 예약된 엔진 설치 비용만 확정 차감하고 결과를 한 번만 굴린다. 예산은 설계 진입 때 이미 차감했으므로 중복 차감하지 않는다.

## 6. 구현 단계

### Phase 1. 엔진 프리셋 연구 모델

- `EnginePresetId`, `EngineStatId`, `TestVisibility` 정의
- 엔진 프리셋 최대 10개 상태 생성
- 시작 시 개발된 프리셋 1개만 활성화
- `새로운 엔진 개발`로 다음 프리셋 활성화
- 일반/집중 연구 구현
- 점수 입력에 따른 선택 스탯 증가 구현
- 완성도 100 상한 처리
- 발사 미션별 연구 버튼 제거

### Phase 2. 연구 운영 UI

- 프리팹 기반 연구 운영 UI 구성
- 허브 상태: `TopInfoBar`(제목 + 칩 3개 + `ResetButton`)와 `HubActionBar`(`PartDevelopmentButton`, `EnterDesignButton`, `WaitQuarterButton`)
- 부품 개발 패널: `EnginePresetColumn`(카드 + `CreateEnginePresetButton`)과 `DetailColumn`/`SelectedPanel`
- `SelectedPanel` 구성 순서: `SelectedEngineText` → `SelectedEngineCompletion` → `StatRows`(`StatRow_*`/`StatRowLabel_*`/`StatGauge_*`) → `StatButtons` → `ResearchModeButtons` → `StartDevelopmentRow`
- `HubActionBar`는 `TopInfoBar`/`EnginePresetColumn`/`DetailColumn`과 달리 전환 애니메이터 대상이 아니므로 설계 전환 때 즉시 숨긴다
- 개발된 엔진 프리셋 카드만 표시
- 선택 엔진 상세 스탯과 스탯별 게이지 표시
- 기본/집중은 모드 선택, `개발 시작`만 미니게임 실행
- 날씨/환경/예보 문구 제거

### Phase 3. 설계 진입 경계

- `ResearchDesignEntryData` 생성
- `ResearchFlowSession`에서 모델과 pending 설계 데이터 보존
- 설계 진입 성공 시 연구 화면 숨김
- 같은 씬 안에서 설계 화면 표시
- 연구 단계 복귀 시 pending 설계 데이터만 삭제

### Phase 4. 임시 설계 화면

- 설치할 엔진 프리셋 선택
- 엔진 설치 개수와 예약 비용 표시
- 설계 적합도 임시 조절
- 공개/비공개 테스트 선택
- 달 착륙은 `FINAL MISSION` 표시
- 실제 설계 조작은 별도 담당이 교체 가능하게 느슨하게 유지

### Phase 5. 발사 확정과 결과

- 발사 버튼에서만 예약 설치 비용 확정 차감
- 설치 엔진 성능, 직전 미션 최고 등급, 발사 경험, 설계 적합도, 공개성 보정으로 성공률 계산
- 발사 결과는 한 번만 고정
- 결과 보상과 분기 연구비 변화를 한 번만 적용
- C 이상이면 다음 단계 해금
- 저전력 검증 시험 B 이상이면 승리

## 7. 테스트 기준

- 일반 연구는 선택 엔진만 완성도와 선택 스탯 증가
- 집중 연구는 선택 엔진만 일반 연구와 같은 완성도, 더 큰 선택 스탯 증가
- 완성도는 100을 넘지 않음
- 완성도 100인 엔진은 모든 연구 버튼 비활성화
- 새 게임 시작 시 표시되는 엔진 프리셋은 1개
- 새 엔진 개발은 10개를 초과하지 않음
- 최대 10개 엔진 프리셋은 같은 초기 스탯과 비용
- 미개발 엔진 프리셋은 연구/설계 설치 대상으로 선택할 수 없음
- 발사 미션에는 연구 진행도 없음
- 설계 진입은 예산만 소비하고 분기/발사 횟수/완성도 미소비
- 발사 확정은 예약 설치 비용/분기/발사 횟수/보상/손실 적용
- 결과 재표시와 버튼 연타로 보상 중복 없음
- 날씨/환경 예보/발사창 보정 상태 없음
- 정식 UI가 프리팹 기반임
- 부품 개발 패널은 ESC로 닫히고 허브 버튼이 다시 보임. 그 ESC로 일시정지 메뉴는 열리지 않음
- 기본/집중 연구 버튼은 모드 선택이며 `개발 시작`만 미니게임을 엶
- 자금이 집중 연구비 아래로 떨어지면 연구 모드가 기본으로 되돌아감

## 8. 현재 구현 메모

연구 컨트롤러 아래에는 `ResearchOperationCanvas` 인스턴스 하나만 둔다. `ResearchOperationScreen`은 원본 프리팹 이름이며 별도의 화면이 아니다. 원본 이름으로 배치된 인스턴스가 있으면 초기화와 씬 설치 코드가 이를 재사용한다.

엔진 이름 편집 카드는 아이콘을 30x30으로 고정하고 이름·입력칸·완성도 텍스트를 아이콘 오른쪽에 배치한다. 이름 편집 때문에 가로 자동 레이아웃을 제거한 뒤에도 이 배치는 유지되어야 하며, 아트 재적용 시에도 동일한 배치 함수를 사용한다.

점화 순서 미니게임은 `Reliability_Button/reliability.png` 배경과 `Button.png` 버튼을 사용한다. 버튼은 빨강, 주황, 청록, 파랑의 2x2 배치이며 `Border/UI/IgnitionButton` 셰이더가 `ButtonTintMask.png`로 버튼 중앙만 발광 색으로 바꾼다. `Border/Research/Apply Ignition UI Art` 메뉴로 기존 미니게임 프리팹에 다시 적용할 수 있다. 순서 생성과 점수 계산은 기존 미니게임 로직을 사용한다.

### 냉각·연료·출력 미니게임 규칙

- 냉각은 파이프 중앙 밸브를 마우스로 시계 방향 드래그하는 단일 도전이다. 목표는 매번 4~6바퀴(1440~2160도)에서 무작위 선택한다. 각도 차이는 ±180도 안으로 보정하며, 역회전은 진행을 줄이되 0 미만이 되지 않는다. 밸브 짧은 변의 12% 이내 중심 영역에서는 기준 각도를 해제해 튐을 막고 다시 잡을 때 새 기준을 만든다.
- 냉각은 시작부터 9초 동안 과열된다. 파이프만 붉게 발광하고 핸들은 원래 색을 유지한다. 회전 수와 진행률을 표시하며, 9초 전에 목표 달성 시 `round(80 + 20 * (1 - elapsed / 9))`점, 목표 미달 또는 9초 이상이면 0점이다.
- 연료 바늘의 최소와 최대는 원본 흰 눈금 양 끝이다. 허브 픽셀 (64,85)을 기준으로 바늘 각도는 +69도부터 -68도까지 움직인다. 하늘색 띠의 -39.4~-62.7도가 합격 구간이며, 중앙은 100점이고 양 끝은 80점이다. 구간 밖은 거리 비례 0~49점이다. 채움은 눈금 안쪽에 표시해 원본 흰 선과 합격 띠를 가리지 않는다.
- 연료는 3회 도전하며 최소에서 최대까지 걸리는 시간은 매번 2.5~3.5초다. 최대를 넘어 계속 누르면 바늘은 끝에 머물고 2초 동안 빨개지며 초당 50점 감점하고 자동 확정한다. 하단 표시부도 눈금 진행량을 표시한다. 최종 점수는 3회 평균이며, 판정 중 입력과 늦은 놓기는 다음 시도를 소비하지 않는다. 영역 밖에서 놓아도 현재 누름을 확정한다.
- 출력은 30/60/100%의 3단계다. 단계마다 목표 중심을 트랙의 0.08~0.92에서 무작위 선택해 고정한다. 목표 전체 폭은 16%, 중앙 노란 영역은 4%다. 커서 편도 왕복 시간은 차례로 0.9/0.75/0.6초이며 단계마다 클릭 기회는 한 번이다.
- 출력은 커서 중심과 목표 중심의 절대 오차가 0.02 이하면 `Perfect` 100점, 0.08 이하면 `Great` 80점, 그 밖은 `Miss` 0점이다. 경계에서는 Perfect가 우선한다. 단계별 5초 미입력도 0점으로 확정하고 최종 점수는 3단계 평균을 반올림한다.
- UGUI 마스크 기반 머티리얼로 색상과 발광을 제어한다. 연료 제공 마스크는 하단 표시부용이며 반원 내부 채움은 별도로 구성한다. 점화의 랜덤 순서, 클릭 0.18초 발광, 셰이더와 공유 머티리얼은 유지한다. 안내는 게임마다 한 문장으로 두고 입력은 기존 Input System과 UGUI 포인터 이벤트를 사용한다. 포커스 손실 시 누름·드래그를 해제하고 재시작 시 진행과 발광을 초기화한다.

검증 기준은 연료 미충전·완충·과충전 자동 확정과 중복 놓기, 냉각 각도 경계·역회전·중심 영역·재드래그·성공·과열, 출력 목표 시드 재현·왕복 속도·판정 경계·연타·시간초과, 결과 닫기 후 보상 1회 적용이다. 테스트 코드는 `ResearchPrototypeModelTests`에서 실제 Tick 및 입력 공통 경로를 사용한다. 이 변경의 빌드·Unity EditMode 실행과 1920x1080/1280x720/960x720 Game View 조작 검증은 통합 담당자가 수행하며, 테스트 추가만으로 실행 통과를 의미하지 않는다.

현재 임시 구현은 실제 설계 담당자가 막히지 않도록 설계 화면을 단순 UI로 둔다. 진짜 설계 조작, 로켓 배치, 3D 연출은 별도 담당자가 교체할 수 있다.

추천 구현 원칙:

- 모델은 순수 C#에 가깝게 유지
- UI 프리팹은 `ResearchPrototypeModel`과 `ResearchFlowSession`을 읽고 쓰는 얇은 레이어로 유지
- 설계 화면은 pending 데이터를 수정하고 발사 확정만 모델에 위임
- 결과 적용은 반드시 한 번만 수행
