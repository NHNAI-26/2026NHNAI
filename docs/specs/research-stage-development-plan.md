# 연구 단계 개발 계획

> 개정일: 2026-09-06
>
> 기준: 실제 물리 발사 구조

## 1. 범위

연구 단계는 `01_Main.unity` 안에서 캠페인 운영, 엔진 프리셋 개발, 미션 선택과 설계 진입을 담당한다. 실제 조립과 발사는 각각 설계 화면과 시뮬레이션 화면이 담당한다.

## 2. 엔진 프리셋

```text
presetId
unlocked
completion
fuelCapacity
cooling
maxOutput
ignitionReliability
```

- 프리셋은 최대 10개다.
- 시작 시 엔진 01만 열린다.
- 새 엔진 개발로 다음 프리셋을 순서대로 연다.
- 완성도는 네 스탯이 공유하는 연구 가능량이다.
- 완성도 100에서는 추가 연구를 막는다.
- 연구는 선택한 프리셋과 스탯만 바꾼다.

## 3. 운영 화면

허브에는 날짜와 남은 분기, 보유 연구비, 분기 연구비를 표시한다. 주요 행동은 `부품 개발`, `로켓 설계`, `건너뛰기`다.

부품 개발 패널에는 아래 요소를 둔다.

- 개발된 엔진 프리셋 목록
- 새 엔진 개발
- 선택 엔진의 완성도
- 네 스탯의 수치와 게이지
- 기본·집중 연구 모드
- 개발 시작

미션 결과는 별도 결과 매체가 담당한다. 운영 화면에 과거 결과 요약이나 결과 예측을 중복 표시하지 않는다.

## 4. 연구 미니게임

- 연료: 게이지 입력값으로 점수를 확정한다.
- 냉각: 밸브 조작으로 열을 관리한다.
- 출력: 움직이는 커서를 목표 영역에서 고정한다.
- 점화: 정해진 순서를 입력한다.

점수는 선택 스탯의 증가량을 정한다. 연구 행동을 다시 성공·실패로 나누지 않는다. 결과 닫기 시 성장 적용 콜백을 한 번만 실행한다.

## 5. 미션 상태

```text
missionId
unlocked
completed
attemptCount
```

시작 시 첫 미션만 열린다. 실제 발사에서 미션 조건을 처음 충족하면 완료 상태를 기록하고 다음 미션을 연다. 마지막 미션을 완료하면 승리한다.

## 6. 설계 진입

1. 열린 미션을 선택한다.
2. 설계 진입 비용을 확인한다.
3. 일반 미션은 공개·비공개를 고른다.
4. 비용을 한 번 차감하고 설계 화면을 연다.
5. 취소하면 설치 예약만 버리고 운영 화면으로 돌아온다.

공개 여부는 결과 매체와 후속 이벤트에만 전달한다.

## 7. 발사 결과 수신

연구 세션은 시뮬레이션에서 아래 결과만 받는다.

```text
runId
missionId
succeeded
terminationReason
telemetry
visibility
usedEnginePresetIds
```

세션은 같은 `runId`를 두 번 적용하지 않는다. 성공 시 진행 상태를 갱신하고, 후속 이벤트를 한 번 정산한 뒤 결과 매체를 표시한다.

## 8. 종료 처리

- 최종 미션 성공은 같은 분기 안에서 기간 만료보다 우선한다.
- 남은 분기가 없고 최종 미션을 완료하지 못했으면 실패 특별호 뒤 패배 화면으로 이동한다.
- 종료 뒤에는 추가 행동과 중복 정산을 막는다.
- 새 게임은 날짜, 자금, 엔진, 미션, 대기 결과와 실행 ID를 초기화한다.

## 9. 검증

- 연구는 선택 프리셋과 선택 스탯에만 적용된다.
- 완성도와 스탯은 0~100을 벗어나지 않는다.
- 새 엔진은 10개를 넘지 않는다.
- 설계 진입 비용과 설치 비용이 중복 차감되지 않는다.
- 실제 미션 성공만 다음 미션을 연다.
- 결과 재표시와 버튼 연타가 성장, 비용, 해금과 이벤트를 반복하지 않는다.
- 공개 여부를 바꿔도 발사 물리와 미션 평가가 바뀌지 않는다.

## 10. 남은 구현 정리

현재 런타임에 과거 결과 모델을 위한 호환 필드와 이벤트 분기가 남아 있다. 새 기능은 여기에 의존하지 않는다. 호출부, UnityEvent와 직렬화 참조를 확인한 뒤 코드 정리 작업에서 성공/실패 이벤트와 실제 텔레메트리 모델로 축소한다.
