# 미션 성공 연출

## 준비된 에셋

`Assets/03. Prefabs/Simulation/Success/`에 낙하산 프리팹과 흔들림 클립을 준비했습니다.
프리팹과 편집기용 미리보기 도구를 구현했으며, 실제 미션 판정과 카메라 전환에는 아직 연결하지 않았습니다.

```text
MissionSuccessParachute
└── DescentRoot                 하강 이동, Animator
    └── SwayPivot               낙하산 안쪽의 흔들림 축
        ├── ParachuteVisual     기존 parachute.fbx와 머티리얼
        └── RocketSwingPivot    연결부를 중심으로 로켓을 흔드는 Empty
            └── RocketSocket    로켓 상단을 맞출 빈 연결점
```

- `MissionSuccessParachute.prefab`: 로켓이 포함되지 않은 낙하산 프리팹입니다. 루트와 부착점의 스케일은 1입니다.
- `ParachuteSway.anim`: 낙하산의 `SwayPivot`은 Z축으로 ±9° 흔들립니다. `RocketSwingPivot`은 0.35초 늦은 반대 위상의 상대 Z 회전 ±16°와 앞뒤 X 회전 ±3°를 더합니다. 전체 클립은 4초, 앞뒤 흔들림은 2초 주기이며 시작과 끝의 각도와 속도가 이어집니다.
- `RocketSwingPivot`의 위치는 낙하산 하단 연결부에 고정합니다. `RocketSocket`의 로컬 위치는 0이므로 로켓이 따로 흔들려도 연결점이 벌어지지 않습니다.
- Timeline의 Animation Track에 `DescentRoot`의 Animator를 연결하고 흔들림 클립을 배치합니다. Animator Controller는 비워 두었으므로 자동으로 재생하지 않습니다.

## 디버그 미리보기

Unity 메뉴에서 **Tools > Border > Debug > Parachute Preview**를 선택합니다.
Play Mode에 들어가지 않아도 전용 창에서 낙하산 연출을 볼 수 있습니다.
창을 열면 로켓과 낙하산이 보이는 중간 프레임에서 시작합니다.

1. **현재 씬 로켓**을 누르거나 **로켓 원본**에 조립된 `Rocket` 루트를 넣습니다. 원본을 비우면 기본 로켓 몸통으로 표시합니다.
2. **기준 고도**와 **하강 시간**을 설정합니다.
3. **처음부터 재생**을 누르면 빈 화면에서 시작해 로켓과 낙하산이 위에서 내려옵니다. **일시정지 / 계속 재생**과 **재생 위치** 슬라이더로 원하는 구간을 확인합니다.
4. 화면 아래로 사라지면 **신문 / 보상 종료 대기** 상태를 유지합니다. **보상 대기 종료**를 누르면 연출을 끝냅니다.

`ParachuteDebugWindow`는 UI Toolkit 창이며, `ParachutePreviewSession`이 별도 미리보기 공간에서
하강과 흔들림을 Timeline으로 평가합니다. 현재 로켓의 몸통과 엔진 메시만 복사하므로 원본의 부모,
위치, 물리와 게임 진행 상태를 변경하지 않습니다. 실행 중에 원본 외형을 바꿨다면 **현재 씬 로켓**이나
**처음부터 재생**을 눌러 다시 가져옵니다. 창을 닫거나 스크립트를 다시 컴파일하면 미리보기 자원을 해제합니다.

이 창의 고도는 수동 입력값이며, 보상 대기 종료 버튼으로 완료 신호를 대신합니다.
실제 비행 카메라에서의 전환, 미션별 고도 조회와 신문 UI 호출은 후속 연결 범위입니다.

## 현재 로켓 부착 규칙

연출을 연결할 때는 비행 중인 `Rocket` 루트 전체를 `RocketSocket` 아래로 옮깁니다.
엔진과 몸통을 함께 옮기며, 별도 로켓을 생성하지 않습니다.

부착 전에 원래 부모와 로컬 위치, 회전, 스케일을 보관하고 `Rocket.StopFlight()`로 물리를 멈춥니다.
월드 크기를 유지한 채 로켓을 세우고, 몸통 상단이 연결점에 닿도록 로켓 중심을 아래로 보정합니다.
`RocketSocket`은 몸통 중심이 아니므로 로컬 위치를 무조건 0으로 지정하면 낙하산 줄과 몸통이 겹칩니다.
현재 `SimulationTest`의 몸통 상단은 로켓 중심에서 3m 위에 있지만, 실제 연결에서는 몸통 크기로 계산합니다.
연출 프리팹을 제거하기 전에 로켓을 원래 부모로 돌려놓습니다.

## 다음 Timeline 연결 범위

1. 단계 미션 성공 시 해당 미션 고도를 기준으로 연출 위치를 배치합니다.
2. 비행 카메라에서 연출 카메라로 전환합니다. 첫 화면에는 로켓이 보이지 않습니다.
3. 현재 로켓을 낙하산 아래에 부착하고, 화면 위에서 천천히 내려오게 합니다.
4. 하강 중 흔들림 클립을 반복하고, 로켓 전체가 화면 아래로 사라지게 합니다.
5. 신문 또는 보상 화면이 끝날 때까지 대기한 뒤 연출을 종료합니다.

현재 `LaunchMissionController.Finish()`는 정지 후 완료 콜백을 호출합니다.
후속 작업에서는 이 완료 흐름과 시뮬레이션 씬의 수명을 조정해 연출 도중 로켓이 해제되지 않게 해야 합니다.

## 검증

Unity 미리보기 렌더에서 로켓을 임시로 부착해 1, 2, 3초의 자세를 확인했습니다.
낙하산과 로켓이 서로 다른 각도로 기울어지고, 로켓이 반동해도 낙하산 하단 연결부가 유지됩니다.
검증용 로켓과 이미지는 제거했습니다.

2026-09-05에 별도 프로젝트 복사본에서 Unity 6000.3.10f1 batchmode PlayMode 테스트
`Simulation.Tests.ParachutePresentationTests` 3개를 실행했고 모두 통과했습니다. 실행 시간은 5.36초입니다.

- 빈 부착점, 낙하산 아래의 연결 위치, 머티리얼과 셰이더 참조 확인
- 화면 밖에서 5.2초 이상 실제 Timeline 재생, 낙하산과 로켓의 독립적인 흔들림과 반복, 연결점과 미션 기준 위치 유지 확인
- 테스트용 `Rocket`의 비행 정지, 부착 후 물리 간섭과 크기 변화 없음, 엔진 자식 유지, 분리 후 프리팹 제거 시 로켓 생존 확인

테스트 코드와 에셋은 원본 작업 공간과 동일한 파일로 검증했습니다. 결과 XML은
`Logs/parachute-motion-playmode.xml`에 저장했습니다. Unity 컴파일은 통과했으며,
`dotnet` 실행 파일이 없어 별도 C# 빌드 명령은 실행하지 못했습니다.
실제 미션의 자동 부착, 카메라 전환과 신문 대기는 아직 미구현이므로 이번 검증에 포함하지 않았습니다.

디버그 도구는 batchmode EditMode 테스트 `ParachuteDebugPreviewTests` 7개를 통과했습니다.
고도 0m, 200m, 10,000m에서 화면 위 진입과 아래 퇴장, 흔들림, 보상 대기를 확인했습니다.
일시정지, 시간 이동, 재시작, 원본 로켓 및 엔진 보존, 자원 해제도 검증했습니다.
로켓의 지연 반동, 연결점 유지와 반복 경계에서 회전이 튀지 않는 것도 확인했습니다.
Unity 창에서 실제 재생, 보상 대기 종료와 슬라이더 조작을 확인했고, 결과 XML은
`Logs/parachute-motion-editmode.xml`에 저장했습니다.
