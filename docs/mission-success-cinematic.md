# 미션 성공 연출

## 준비된 에셋

`Assets/03. Prefabs/Simulation/Success/`에 낙하산 프리팹과 흔들림 클립을 준비했습니다.
실제 미션 성공 시 `MissionSuccessPresentation`이 비행 카메라의 추적을 1초 동안 멈춘 뒤,
현재 로켓을 낙하산에 부착하고 전용 카메라에서 6초 동안 하강시킵니다. 전체 연출은 7초입니다.

```text
MissionSuccessParachute
└── DescentRoot                 하강 이동, Animator
    └── SwayPivot               낙하산 안쪽의 흔들림 축
        ├── ParachuteVisual     기존 parachute.fbx와 머티리얼
        └── RocketSwingPivot    연결부를 중심으로 로켓을 흔드는 Empty
            └── RocketSocket    로켓 상단을 맞출 빈 연결점
```

- `MissionSuccessParachute.prefab`: 로켓이 포함되지 않은 낙하산 프리팹입니다. 루트와 부착점의 스케일은 1입니다.
- `ParachuteSway.anim`: 낙하산의 `SwayPivot`은 Z축으로 ±9° 흔들립니다. `RocketSwingPivot`은 0.35초 늦은 반대 위상의 상대 Z 회전 ±16°와 앞뒤 X 회전 ±3°를 더합니다. 전체 클립은 4초, 앞뒤 흔들림은 2초 주기이며 시작과 끝의 각도와 속도가 이어집니다.
- `RocketSwingPivot`의 위치는 낙하산 하단 연결부에 고정합니다. `RocketSocket`의 로컬 위치는 0이므로 로켓이 따로 흔들려도 연결점이 벌어지지 않습니다.
- 런타임에서는 Animation Playable Graph로 `DescentRoot`의 Animator에 흔들림 클립을 연결합니다. 프리팹만 생성하면 자동 재생하지 않으며, 성공 처리에서 시작합니다. 디버그 미리보기는 기존 Timeline을 사용합니다.

## 디버그 미리보기

Unity 메뉴에서 **Tools > Border > Debug > Parachute Preview**를 선택합니다.
Play Mode에 들어가지 않아도 전용 창에서 낙하산 연출을 볼 수 있습니다.
창을 열면 로켓과 낙하산이 보이는 중간 프레임에서 시작합니다.

1. **현재 씬 로켓**을 누르거나 **로켓 원본**에 조립된 `Rocket` 루트를 넣습니다. 원본을 비우면 기본 로켓 몸통으로 표시합니다.
2. **기준 고도**와 **하강 시간**을 설정합니다.
3. **처음부터 재생**을 누르면 빈 화면에서 시작해 로켓과 낙하산이 위에서 내려옵니다. **일시정지 / 계속 재생**과 **재생 위치** 슬라이더로 원하는 구간을 확인합니다.
4. 화면 아래로 사라지면 **신문 / 보상 종료 대기** 상태를 유지합니다. **보상 대기 종료**를 누르면 연출을 끝냅니다.

`ParachuteDebugWindow`는 UI Toolkit 창이며, `ParachutePreviewSession`이 별도 미리보기 공간에서
하강과 흔들림을 Timeline으로 평가합니다. 현재 로켓의 몸통과 엔진 메시만 복사하므로 원본의 부모,
위치, 물리와 게임 진행 상태를 변경하지 않습니다. 실행 중에 원본 외형을 바꿨다면 **현재 씬 로켓**이나
**처음부터 재생**을 눌러 다시 가져옵니다. 창을 닫거나 스크립트를 다시 컴파일하면 미리보기 자원을 해제합니다.

이 창의 고도는 수동 입력값이며, 보상 대기 종료 버튼으로 완료 신호를 대신합니다.
실제 게임은 성공 순간 로켓의 월드 위치에서 추적 해제를 시작하며, 총 7초 후 기존 신문 UI 흐름으로 복귀합니다.
디버그 미리보기는 낙하산 하강만 표시하므로 추적 해제와 효과음은 실제 성공 흐름에서 확인합니다.

## 현재 로켓 부착 규칙

비행 중인 `Rocket` 루트 전체를 `RocketSocket` 아래로 옮깁니다.
엔진과 몸통을 함께 옮기며, 별도 로켓을 생성하지 않습니다.

부착 전에 원래 부모와 로컬 위치, 회전, 스케일을 보관하고 `Rocket.StopFlight()`로 물리를 멈춥니다.
월드 크기를 유지한 채 로켓을 세우고, 몸통 상단이 연결점에 닿도록 로켓 중심을 아래로 보정합니다.
`RocketSocket`은 몸통 중심이 아니므로 로컬 위치를 무조건 0으로 지정하면 낙하산 줄과 몸통이 겹칩니다.
현재 `SimulationTest`의 몸통 상단은 로켓 중심에서 3m 위에 있지만, 실제 연결에서는 몸통 크기로 계산합니다.
연출 프리팹을 제거하기 전에 로켓을 원래 부모로 돌려놓습니다.

## 실제 성공 흐름

최종 미션(`LowPowerZoneHold`)을 B 이상으로 통과한 발사는 이 연출을 재생하지 않습니다.
`SimulationStageHost.CompleteLaunch`가 `result.FinalMissionWon`을 보고 낙하산과 결과 신문을 모두 건너뛴 뒤
해피엔딩 시네마틱으로 넘깁니다. 신문은 그 시네마틱의 마지막 비트에서 한 번만 나옵니다.
자세한 것은 `docs/specs/happy-ending-cinematic-spec.md`. 아래는 그 외 모든 성공에 해당합니다.

`SimulationStageHost.CompleteLaunch(true)`에서 등급과 보상을 확정한 뒤 연출을 시작합니다.
`RocketBody.prefab`의 `MissionSuccessPresentation`은 상위의 실제 `Rocket`을 찾아 사용하므로
몸통 프리팹에 별도 로켓이나 Rigidbody를 만들지 않습니다.

1. 기존 사진과 성공 순간의 속도를 보관하고 로켓 물리를 정지합니다.
   `RocketBuilder`, `CinemachineBrain`, `SkyEnvironment` 갱신을 멈춰 비행 카메라를 고정합니다.
   로켓은 보관한 속도로 1초 동안 계속 이동하며, 이 구간에는 기존 화면과 UI를 유지합니다.
   추적을 멈춘 직후 `parachuteBGM.mp3`를 시작하고, 기존 BGM에서 0.25초 동안 전환합니다.
   BGM은 낙하산 카메라 전환과 효과음 재생 중에도 이어지며, 이후 화면의 기존 BGM 처리에 따릅니다.
2. 추적 해제 1초 후의 로켓 위치를 기준으로 낙하산을 배치하고, 로켓 몸통 상단을 연결점에 맞춥니다.
3. 시뮬레이션 카메라·조작·UI·고도 환경 갱신을 잠시 멈추고 전체 화면 연출 카메라로 전환합니다.
   다른 씬의 CRT 출력 카메라보다 나중에 렌더링해 낙하산 화면이 가려지지 않도록 합니다.
   발사대와 지형 등 주변 렌더러는 잠시 숨겨 낮은 고도 성공에서도 낙하산을 가리지 않게 합니다.
4. 첫 화면 위에서 시작해 화면 아래로 완전히 빠져나갈 때까지 **총 6초** 동안 내려옵니다.
   화면에 진입하기 약 0.15초 전에 `parachute.mp3`를 2D 단발 효과음으로 한 번 재생합니다.
   로켓과 엔진의 렌더러 범위를 흔들림까지 반영해 미리 평가하므로 크기와 화면 비율에 맞춰 재생 시점이 달라집니다.
   `parachuteSoundLeadSeconds`로 선행 시간을 조정하며, 중단하거나 종료하면 해당 효과음도 정리합니다.
   흔들림은 반복하며, 시간은 `realtimeSinceStartupAsDouble`의 시작 시각 차이를 사용해 타임스케일과 첫 프레임 지연의 영향을 받지 않습니다.
5. 로켓을 원래 부모와 위치로 되돌리고 임시 카메라·낙하산·Playable Graph를 제거합니다.
6. 기존 결과 신문을 표시하고, 신문을 닫으면 시뮬레이션 씬을 내립니다. 성공에는 기존 3초 대기를 추가하지 않습니다.

실패가 확정되면 `failBGM.mp3`를 시작하고 기존 음악에서 0.25초 동안 전환합니다.
`launchResultHoldSeconds`(기본 3초) 동안 재생하며, 결과 화면이 열릴 때 기존 BGM 종료 처리를 따릅니다.
성공 연출의 필수 참조가 누락된 경우에도 기존 대기·복귀 경로로 진행합니다. 연출 중 복귀 버튼은 기존 `busy` 상태로
차단하며, 컴포넌트 비활성화 시에도 로켓 분리와 카메라 복원을 처리합니다.

## 추적 해제 및 효과음 검증

2026-09-06에 원본과 같은 코드 및 에셋을 사용하는 별도 프로젝트 복사본에서 검증했습니다.
Unity 컴파일, `LaunchMissionControllerTests` 18개, 성공 연출 관련 PlayMode 테스트 11개가 통과했습니다.
PlayMode 검증에는 실제 `SimulationTest` 씬의 임시 캡처 테스트 1개가 포함됩니다.

카메라 위치와 회전 고정, 1초 전환 경계, 타임스케일 0에서의 연출 평가, 중간 비활성화 시 복원을 확인했습니다.
가로 및 세로 화면과 서로 다른 로켓 크기에서 효과음이 화면 진입 0.13~0.17초 전에 한 번 재생되고,
연출 종료 시 정리되는 것도 확인했습니다. 효과음은 `SoundDatabase`의 `parachute` 항목에 등록했으며 미리 로드합니다.

실제 씬의 0, 0.5, 0.99, 1, 1.5, 3, 5, 7초 카메라 렌더를 검증한 뒤 이미지를 삭제했습니다.
결과는 `Logs/success-cue-editmode.xml`과 `Logs/success-cue-playmode.xml`에 저장했습니다.
전체 테스트와 실제 비행으로 미션을 완주하는 과정은 재실행하지 않았습니다.
현재 작업 공간에 솔루션 파일이 없어 별도 `dotnet build`는 실행하지 않았습니다.

낙하산 BGM 연결 후 `MissionSuccessPresentationTests` 8개를 별도 복사본에서 다시 실행해 모두 통과했습니다.
추적 정지 직후 재생, 기존 음악의 0.25초 전환 종료, 카메라 전환 시 재시작 방지와 효과음 동시 재생을 확인했습니다.
결과는 `Logs/parachute-bgm-playmode.xml`에 저장했습니다. 실제 미션 완주는 재실행하지 않았습니다.

원격 CRT 화면 변경을 통합한 뒤 `MissionSuccessPresentationTests` 9개가 통과했습니다.
별도 씬의 CRT 카메라보다 낙하산 카메라가 나중에 렌더링되는지도 검증했습니다.
결과는 `Logs/pull-success-playmode.xml`에 저장했습니다.

실패 BGM 연결 후 같은 테스트 클래스의 11개 테스트가 통과했습니다.
실패 대기 시작 시 음악 전환과 성공 경로의 실패 음악 미재생을 확인했으며, 결과는 `Logs/fail-bgm-playmode.xml`에 저장했습니다.

## 검증

Unity 미리보기 렌더에서 로켓을 임시로 부착해 1, 2, 3초의 자세를 확인했습니다.
낙하산과 로켓이 서로 다른 각도로 기울어지고, 로켓이 반동해도 낙하산 하단 연결부가 유지됩니다.
검증용 로켓과 이미지는 제거했습니다.

2026-09-05에 별도 프로젝트 복사본에서 Unity 6000.3.10f1 batchmode PlayMode 테스트
`Simulation.Tests.ParachutePresentationTests` 3개를 실행했고 모두 통과했습니다. 실행 시간은 5.36초입니다.

- 빈 부착점, 낙하산 아래의 연결 위치, 머티리얼과 셰이더 참조 확인
- 화면 밖에서 5.2초 이상 실제 Timeline 재생, 낙하산과 로켓의 독립적인 흔들림과 반복, 연결점과 미션 기준 위치 유지 확인
- 테스트용 `Rocket`의 비행 정지, 부착 후 물리 간섭과 크기 변화 없음, 엔진 자식 유지, 분리 후 프리팹 제거 시 로켓 생존 확인

테스트 코드와 에셋은 원본 작업 공간과 동일한 파일로 검증했습니다. 결과 XML은
`Logs/parachute-motion-playmode.xml`에 저장했습니다. Unity 컴파일은 통과했으며,
`dotnet` 실행 파일이 없어 별도 C# 빌드 명령은 실행하지 못했습니다.
위 기록은 프리팹 단독 검증 당시 결과입니다. 런타임 연결 검증은 아래 기록을 참조합니다.

디버그 도구는 batchmode EditMode 테스트 `ParachuteDebugPreviewTests` 7개를 통과했습니다.
고도 0m, 200m, 10,000m에서 화면 위 진입과 아래 퇴장, 흔들림, 보상 대기를 확인했습니다.
일시정지, 시간 이동, 재시작, 원본 로켓 및 엔진 보존, 자원 해제도 검증했습니다.
로켓의 지연 반동, 연결점 유지와 반복 경계에서 회전이 튀지 않는 것도 확인했습니다.
Unity 창에서 실제 재생, 보상 대기 종료와 슬라이더 조작을 확인했고, 결과 XML은
`Logs/parachute-motion-editmode.xml`에 저장했습니다.

## 기존 런타임 연결 검증

`MissionSuccessPresentationTests` 3개와 기존 `ParachutePresentationTests` 3개를 통과했습니다.
상위 로켓 전체 부착, 0·3·6초 화면 위치, 크기와 엔진 유지, 카메라·주변 렌더러 복원,
중간 비활성화와 프리팹 참조를 확인했습니다. 실제 SimulationTest 카메라 렌더에서도
낙하산과 로켓을 확인했고 검증 이미지는 삭제했습니다.

메인 씬에서 성공 판정을 테스트용으로 발생시켜, 연출 시작부터 6초 경과 후 결과 신문 표시와
시뮬레이션 씬 해제까지 확인했습니다. 실제 비행으로 성공 조건에 도달하는 전 과정은 재실행하지 않았습니다.
추가 오디오 회귀 검증은 SteamAudio 종료 예외로 Test Runner가 중단되어 완료하지 못했습니다.
Unity 컴파일은 통과했으며, 이 환경에 dotnet과 프로젝트 솔루션 파일이 없어 별도 dotnet 빌드는 실행하지 않았습니다.
