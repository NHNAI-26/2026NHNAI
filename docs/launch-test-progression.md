# 발사 테스트 미션 예시

> 상태: 보조 기획 예시  
> 목적: 정식 GDD의 0~5 발사 미션을 구체적인 미션 예시로 풀어 쓴다.  
> 기준 문서: `docs/artemis-2026-gdd/04_연구_진행도_단계해금.md`

## 1. 사용 원칙

이 문서는 정식 규칙 문서가 아니라 미션 설계 예시다. 구현 기준은 `docs/artemis-2026-gdd/` 아래 정식 GDD를 따른다.

발사 미션은 기존 `엔진 단계 -> 로켓 단계 -> 궤도 단계 -> 달 착륙 단계` 구조를 쓰지 않는다. 정식 구조는 아래 여섯 미션이다.

1. `StaticFire`: 정적 연소 시험
2. `LowAltitude`: 낮은 고도 도달 시험
3. `HighAltitude`: 높은 고도 도달 시험
4. `TargetZone`: 목표 구역 도달 시험
5. `ZoneHold`: 목표 구역 체류 시험
6. `LowPowerZoneHold`: 저전력 검증 시험

핵심은 "더 멀리 가기" 반복이 아니다. 각 미션은 플레이어에게 새 설계 판단 하나를 가르친다.

## 2. 현실 테스트와 닮은 점

현실 로켓 테스트도 바로 최종 임무로 가지 않는다. 엔진과 추진계를 먼저 검증하고, 낮은 위험의 초기 시험에서 시작해 더 복잡한 통합 조건으로 올라간다.

게임에서는 이 흐름을 아래처럼 단순화한다.

| 현실 테스트 감각 | 게임 미션 |
|---|---|
| 정적 연소·핫파이어 | `StaticFire` |
| 초기 비행 가능성 확인 | `LowAltitude` |
| 성능 한계 확장 | `HighAltitude` |
| 목표 조건 비행 | `TargetZone` |
| 궤도·운용 상태 유지의 축약 | `ZoneHold` |
| 운용 여유와 효율 검증 | `LowPowerZoneHold` |

참고:

- [NASA Product Verification](https://www.nasa.gov/reference/5-3-product-verification/)
- [NASA SLS Core Stage Green Run Testing Overview](https://www.nasa.gov/general/sls-core-stage-green-run-testing-overview/)
- [NASA Artemis Program](https://www.nasa.gov/humans-in-space/artemis/?lv=true)

## 3. 미션 예시

### 0번 미션. 정적 연소 시험

미션 ID: `StaticFire`

목표:

- 로켓을 띄우지 않는다.
- 엔진을 고정 시험대에서 지정 시간 동안 태운다.

예시 성공 조건:

- 연소 시간 `5초` 이상
- 온도 한계 초과 없음
- 점화 실패 없음

플레이어가 배우는 것:

- 엔진 종류
- 작동 시간
- 출력
- 연료 지속 시간
- 냉각/과열
- 점화 신뢰도

실패 예:

- 점화 실패
- 연료 조기 소진
- 과열로 긴급 정지

좋은 이유:

- 현실의 핫파이어와 비슷하다.
- 첫 미션부터 로켓 설계 전체를 요구하지 않는다.
- 엔진 연구가 왜 필요한지 바로 보여준다.

### 1번 미션. 낮은 고도 도달 시험

미션 ID: `LowAltitude`

목표:

- 낮은 목표 고도에 도달한다.
- "이 로켓이 뜨는가"만 확인한다.

예시 성공 조건:

- 최고 고도 `100m` 이상
- 발사대 주변에서 바로 추락하지 않음

플레이어가 배우는 것:

- 총추력
- 엔진 개수
- 최소 점화 시간

실패 예:

- 추력 부족으로 이륙 실패
- 점화 시간이 너무 짧아 목표 미달
- 연료가 너무 빨리 소진

설계 포인트:

- 여기서는 어렵게 만들지 않는다.
- 정답은 대체로 "충분한 힘과 충분한 연소 시간"이면 된다.
- 플레이어가 첫 비행 성공을 경험하는 자리다.

### 2번 미션. 높은 고도 도달 시험

미션 ID: `HighAltitude`

목표:

- 더 높은 목표 고도에 도달한다.
- 단순히 뜨는 수준을 넘어서, 출력을 오래 유지해야 한다.

예시 성공 조건:

- 최고 고도 `300m` 이상
- 또는 플레이테스트 후 `500m` 이상으로 조정

플레이어가 배우는 것:

- 더 긴 연소 시간
- 출력과 연료의 균형
- 과출력과 과열 위험

실패 예:

- 출력이 낮아 최고 고도 부족
- 출력은 높은데 연료 조기 소진
- 냉각 부족으로 중간 출력 저하

설계 포인트:

- 1번과 겉모습은 비슷하지만 배움은 다르다.
- 1번은 "뜰 수 있는가"다.
- 2번은 "충분한 에너지를 유지할 수 있는가"다.
- 2번까지만 단순 고도 목표를 허용한다.

### 3번 미션. 목표 구역 도달 시험

미션 ID: `TargetZone`

목표:

- 고도 조건을 만족하면서 특정 수평 구역에 도달한다.
- 위로만 가는 설계가 정답이 아님을 보여준다.

예시 성공 조건:

- 최고 고도 `200m` 이상
- 수평 거리 `80m~120m` 구역 통과 또는 착지

플레이어가 배우는 것:

- 엔진 각도
- 의도적 수평 속도
- 출력과 방향의 균형
- 비대칭 토크와 방향 전환의 차이

실패 예:

- 각도가 너무 작아 목표 구역 미달
- 각도가 너무 커서 고도 부족
- 비대칭 토크 때문에 구역 도달 전 자세 상실

설계 포인트:

- 발사 중 조종이 없으므로 목표 구역 도달은 발사 전 설계로 해결해야 한다.
- 장애물보다 낫다. 막히는 느낌보다 조준하는 느낌이 난다.

### 4번 미션. 목표 구역 체류 시험

미션 ID: `ZoneHold`

목표:

- 목표 구역에 도달한 뒤 일정 시간 이상 머문다.
- 단순 도달이 아니라 안정적인 도달을 요구한다.

예시 성공 조건:

- 목표 구역 안에서 `3초` 이상 유지
- 자세 오차 `±30도` 이하
- 속도 상한 초과 없음

플레이어가 배우는 것:

- 속도 제어
- 엔진 OFF 타이밍
- 자세 안정
- 목표를 지나치지 않는 설계

실패 예:

- 너무 빨라서 구역을 스쳐 지나감
- 점화 차단이 늦어 목표 구역 초과
- 목표에는 도달했지만 회전이 커져 유지 실패

설계 포인트:

- 이 미션이 핵심 재미가 될 가능성이 높다.
- "맞췄다"에서 끝나지 않고 "안정적으로 맞췄다"까지 요구한다.
- 실제 궤도 유지를 만들지 않고도 비슷한 감각을 준다.

### 5번 미션. 저전력 검증 시험

미션 ID: `LowPowerZoneHold`

목표:

- 4번 미션과 같은 목표를 더 낮은 전력/연료/비용으로 달성한다.
- 최종 미션이다.

예시 성공 조건:

- 4번 미션과 같은 목표 구역에서 `3초` 이상 유지
- 총 점화 시간 `8초` 이하
- 또는 총 출력 사용량 기준 이하
- 또는 설치 엔진 수/설치 비용 기준 이하

플레이어가 배우는 것:

- 효율
- 과잉 설계의 비용
- 성공과 좋은 성공의 차이
- 출력, 연료, 방향, 타이밍의 종합 조율

실패 예:

- 저전력으로 줄이다가 목표 미달
- 엔진을 많이 달아 성공했지만 비용 조건 실패
- 높은 출력으로 빠르게 도달했지만 체류 실패

설계 포인트:

- 새 조작을 많이 추가하지 않는다.
- 이미 배운 4번 미션을 더 깔끔하게 수행하게 한다.
- B 이상이면 게임 승리로 처리한다.

## 4. 이번 버전에서 빼는 것

아래 요소는 나쁘지 않지만, 지금 넣으면 복잡도가 빨리 오른다.

| 요소 | 판단 | 이유 |
|---|---|---|
| 시간차 점화 전용 미션 | 보류 | 재미는 있지만 UI와 설명 부담이 크다. |
| 자세 유지 단독 미션 | 보류 | 4번 미션 체류 조건 안에 섞는 편이 덜 지루하다. |
| 목표 고도 범위 `280m~320m` | 보류 | 4번 미션과 역할이 겹친다. 나중에 고난도 조건으로 쓰면 좋다. |
| 보너스/패널티 존 | 보조로만 | 자동 발사에서는 메인 목표로 약하다. |
| 랜덤 장애물 | 제외 | 설계 게임에서는 억울함이 커진다. |
| 고정 장애물 | 제외 | 맵 제작 부담이 크고 고정 정답이 생기기 쉽다. |

## 5. 넣어도 되는 작은 보조 요소

### 발사 후 시험 리포트

각 발사 후 아래 3개만 보여준다.

- 최고 고도
- 목표 구역 체류 시간
- 총 점화 시간 또는 사용 전력

복잡한 그래프는 필요 없다. 숫자 3개와 짧은 실패 원인 하나면 충분하다.

구현 상태: 셋 다 관제 화면 좌측 발사 정보 패널에 있다(최대 거리·남은 연료·결과가 더 붙는다).
최고 고도는 `LaunchMissionController.MaxAltitude` 로 실제 누적하며, 체류는 `HoldSeconds`,
총 점화는 `Rocket.TotalBurnSeconds` 를 읽는다. 사용 전력은 아직 없다. 자세한 것은
`docs/rocket-simulation.md` 의 "발사 정보 패널".

## 6. 요약

이 미션 구조는 장애물 회피 게임이 아니다. 로켓 테스트처럼 요구 조건을 하나씩 검증하는 구조다.

플레이어는 아래 순서로 배운다.

1. 엔진이 안정적으로 타는가
2. 로켓이 뜨는가
3. 더 높이 갈 수 있는가
4. 원하는 구역으로 갈 수 있는가
5. 그 구역에 안정적으로 머물 수 있는가
6. 같은 일을 더 적은 힘으로 할 수 있는가
