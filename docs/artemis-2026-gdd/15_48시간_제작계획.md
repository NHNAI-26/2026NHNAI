# 15. 48시간 제작 계획

> 상태: **확정**  
> 전제: 소규모 팀 기준. 인원이 적을수록 P1과 P2를 즉시 줄인다.

## 1. 완성 우선 원칙

게임잼에서 가장 중요한 완료 순서는 다음과 같다.

1. 날짜와 2026 마감
2. 연구비와 엔진 프리셋 연구
3. 설계 맵과 발사 시기 판단
4. 로켓 설계 단계
5. 발사 결과 판정
6. 네 3D 자동 시뮬레이션의 성공·실패 분기
7. 결과 반영과 승패
8. 아트·사운드·카메라 개선

3D 장면이 아름답더라도 프로젝트 루프가 연결되지 않으면 미완성이다. 반대로 장면이 단순하더라도 네 설계 단계와 자동 발사가 모두 연결되고 결과가 운영에 반영되면 완성으로 본다.

- 발사 전 연구 단계 복귀
- 성공·부분 성공·실패 확률
- 발사 버튼 이후 결과 고정
- 엔진 자동 3D 시뮬레이션
- 로켓 자동 3D 시뮬레이션

## 3. 권장 시간표

### 0~4시간: 기반과 기획 잠금

- 이 문서의 수치와 범위 확인
- 프로젝트 생성
- `01_Main` 화면 구조와 폴더 구조
- `GameState`, 단계 데이터, 기본 UI 틀
- 임시 큐브와 텍스트로 전체 흐름 스케치
- 역할 분담

4시간 이후 신규 시스템 아이디어를 추가하지 않는다.

### 4~10시간: 운영 루프

- 날짜와 분기
- 연구비
- 엔진 프리셋별 일반·집중 연구
- 엔진 프리셋 레벨과 스탯
- 잠금 조건
- 대기
- 분기 연구비 지급
- 2026 종료

이 시점에는 3D 없이도 버튼으로 한 판이 끝까지 진행되어야 한다.

### 10~15시간: 설계 판정과 공개성

- 성공 확률 공식
- S/A/B/C/F 판정
- 설계 보정 공식
- 엔진 ON/OFF 타이밍 평가
- 엔진 설치 비용 예약과 환불
- 공개/비공개 테스트 보정과 보상
- 설계 화면 임시 UI
- 발사 확인 모달
- `SimRunData` 결과 고정
- 임시 결과 화면으로 경제 반영 검증

### 15~23시간: 설계 화면과 엔진·로켓 장면

- 공통 `DesignSceneController`
- 목표 경로와 예상 경로 표시
- 엔진 프리셋 배치, 부품 위치, 힘, 방향, 엔진 ON/OFF 입력
- 공통 `SimulationDirector`
- 공통 HUD와 카운트다운
- 엔진 정상·C·F 결말
- 로켓 정상·C·F 결말
- A/B는 정상 시퀀스에 경고만 추가
- 설계 오류 효과 최소 연결

### 23~31시간: 궤도·달 장면

- 궤도 기본 경로
- 엔진 타이밍 오류와 통신 오류
- 궤도 성공·부분·실패
- 달 자동 하강
- 달 성공·부분·실패
- 달 착륙 승리 연결

### 31~36시간: 전체 통합

- 네 발사 비용과 결과 적용
- 단계 해금
- 설치 엔진 성능과 직전 단계 최고 등급 반영
- 설계 진입·복귀·발사 확정 흐름
- 마지막 분기 처리
- 결과 중복 방지
- 연구·설계·발사 결과 화면 전환 반복 테스트

### 36~42시간: 아트·VFX·사운드

- 임시 모델 교체
- 엔진 불꽃·연기·폭발
- 경로 라인·엔진 타이밍 마커·노이즈
- 카메라 전환
- 핵심 사운드
- UI 가독성

### 42~46시간: 밸런스와 버그 수정

- 최소 5회 빠른 전체 플레이
- 시간과 자금 막힘 확인
- 확률 표시와 실제 결과 검증
- 공개/비공개 테스트 보상 확인
- 2026 Q4 경계 조건
- 빌드 테스트

### 46~48시간: 제출

- 최종 빌드
- 실행 파일 확인
- 해상도와 입력 확인
- 시작부터 엔딩까지 1회 플레이
- 제출 페이지와 설명
- 비상 빌드 보관

## 5. 지연 시 축소 순서

마감이 위험할 때 아래 순서대로 줄인다.

1. S/A/B 전용 연출을 하나의 성공 연출로 통합
2. 설계 맵 패턴을 단계당 1개로 축소
3. 단계별 사고를 2종으로 축소
4. 설계 오류 전용 VFX를 대표 장면에서만 표시
5. 카메라 수를 장면당 3개로 축소
6. 결과 보고서 세부 지표 제거
7. 관제 음성 제거
8. 프롤로그를 텍스트 2장으로 축소
9. 2배속과 건너뛰기 제거

절대 제거하지 않는 것:

- 네 설계 단계와 자동 발사
- 자동 진행
- 실패 가능성
- 공개/비공개 테스트 선택
- 엔진 ON/OFF 타이밍 설계
- 2026 마감
- 연구비와 엔진 프리셋 상태

## 6. 솔로 개발 비상안

솔로 개발이고 24시간 시점에 진척이 부족하다면:

- 네 발사를 `01_Main` 안의 공통 발사 결과 화면에서 배경과 오브젝트만 교체
- 성공, C, F 세 결말만 시각적으로 구분
- S/A/B는 결과 보고서에서만 등급 구분
- 설계 오류 VFX는 힘 부족, 방향 오류, 엔진 타이밍 오류 세 종류만 제작
- 모든 기체 이동을 Animation 또는 단순 Lerp로 구현
- UI는 단일 운영 화면과 모달로 통합

## 7. 제출 설명용 핵심 문장

> 2017년부터 2026년까지 연구비와 시간을 관리하고, 발사 전에는 맵과 목표 경로를 보고 로켓을 설계하십시오. 공개 테스트는 위험하지만 보상이 크고, 비공개 테스트는 안전하지만 보상이 작습니다. 발사 버튼 이후에는 자동 3D 시뮬레이션이 결과를 보여줍니다.
