# 05. 발사창·환경 이벤트·확률 판정

> 상태: **확정**  
> 이 문서는 게임의 핵심 전략과 공정성을 정의한다.

## 1. 발사창의 역할

현재 분기에는 하나의 주 환경 상태가 존재한다. 환경은 발사 성공률을 올리거나 내리고 설계 단계의 목표 경로와 3D 시뮬레이션의 사고 연출에 영향을 준다.

운영 화면에는 다음 네 분기를 표시한다.

1. 현재 분기
2. 다음 분기
3. 2분기 뒤
4. 3분기 뒤

MVP에서는 예보가 정확하다. 예보 정확도, 오보, 숨겨진 날씨는 만들지 않는다. 2026 Q4 이후 자리는 환경 대신 `PROJECT DEADLINE` 카드로 표시한다.

플레이어는 미래 분기를 직접 선택해 발사할 수 없다. 좋은 환경을 사용하려면 연구 또는 대기로 시간을 실제로 보내야 한다. 설계 단계에 들어갔다가 발사하지 않고 돌아오는 것은 시간을 보내지 않으므로 환경도 이동하지 않는다.

## 2. 환경 상태 표

| ID | 이름 | 생성 가중치 | 엔진 | 로켓 | 궤도 | 달 착륙 | 주요 3D 표현 |
|---|---|---:|---:|---:|---:|---:|---|
| `Stable` | 안정 | 35 | 0 | 0 | 0 | 0 | 평온한 환경 |
| `Ideal` | 최적 발사창 | 15 | +10 | +10 | +10 | +10 | 맑은 하늘, 깨끗한 통신 |
| `HighWind` | 강풍 | 15 | -5 | -20 | 0 | 0 | 구름 이동, 로켓 흔들림 |
| `Thunderstorm` | 뇌우 | 10 | -15 | -25 | 0 | 0 | 비, 번개, 전력 경고 |
| `MeteorShower` | 유성우 | 15 | 0 | -5 | -25 | -20 | 유성 궤적, 근접 통과 또는 충돌 |
| `SolarStorm` | 태양 폭풍 | 10 | 0 | 0 | -20 | -25 | 통신 노이즈, 전자장비 경고 |

수치는 성공 확률에 더하는 퍼센트포인트다.

## 3. 환경 생성 규칙

한 판이 시작될 때 시드를 만든 뒤 36분기의 환경을 미리 생성한다. 플레이어에게는 현재 포함 4분기만 공개한다.

공정성을 위해 아래 제약을 적용한다.

- 같은 위험 환경은 3분기 연속 생성하지 않는다.
- 모든 연속 4분기 창에는 `Stable` 또는 `Ideal`이 최소 한 번 존재한다.
- 한 분기에는 주 환경 하나만 존재한다.
- 대기하거나 씬을 다시 불러도 이미 생성된 환경은 바뀌지 않는다.
- 새 게임을 시작하면 새 시드를 사용한다.

## 4. 성공률 계산

### 4.1 이전 단계 평균

| 발사 | 이전 단계 평균값 |
|---|---|
| 엔진 | 현재 엔진 진행도와 동일하게 취급 |
| 로켓 | 엔진 진행도 |
| 궤도 | 엔진·로켓 진행도의 평균 |
| 달 착륙 | 엔진·로켓·궤도 진행도의 평균 |

### 4.2 공식

엔진 발사:

```text
성공률 =
20
+ 엔진 진행도 × 0.8
+ 발사 경험 보너스
+ 현재 환경 보정
+ 설계 적합도 보정
```

로켓, 궤도, 달 착륙:

```text
성공률 =
20
+ 현재 단계 진행도 × 0.6
+ 이전 단계 평균 진행도 × 0.2
+ 발사 경험 보너스
+ 현재 환경 보정
+ 설계 적합도 보정
```

최종 성공 확률은 반올림한 뒤 `10~90`으로 제한한다.

발사 경험 보너스:

```text
min(해당 단계의 이전 발사 횟수 × 3, 9)
```

### 4.3 설계 적합도 보정

설계 단계에서는 이번 맵의 목표 경로와 플레이어 설계를 비교해 `designFit`을 `0~100`으로 계산한다. 이 값은 실제 궤도역학이 아니라 게임용 평가값이다.

```text
설계 적합도 보정 = round((designFit - 50) × 0.4)
```

따라서 설계 보정 범위는 `-20%p~+20%p`다. 연구 진행도가 높을수록 허용 오차가 넓어져 같은 설계라도 더 높은 `designFit`을 받기 쉽다.

최소 평가 요소:

- 목표 경로와 실제 예상 경로의 거리
- 필요한 방향과 설정한 힘 방향의 차이
- 단계별 필수 부품의 부착 위치
- 총 힘이 목표에 비해 부족하거나 과도한 정도
- 현재 환경이 요구하는 보정 방향 반영 여부

## 5. 결과 확률 표시

설계 단계 HUD에는 현재 설계 기준의 성공, 부분 성공, 실패를 모두 보여준다.

```text
성공: P%
부분 성공: min(15, 95 - P)%
실패: 나머지%
```

예시:

```text
엔진 발사 성공률: 60%
부분 성공: 15%
실패: 25%
```

최종 성공 확률이 90%여도 실패 확률은 최소 5% 남는다.

## 6. 결과 판정

1~100 정수 난수를 한 번 생성한다.

```pseudo
roll = RandomIntInclusive(1, 100)

if roll <= successChance:
    margin = successChance - roll

    if margin >= 50:
        grade = S
    else if margin >= 20:
        grade = A
    else:
        grade = B

else if roll <= min(successChance + 15, 95):
    grade = C
else:
    grade = F
```

- S/A/B는 완전 성공이다.
- C는 부분 성공이다.
- F는 실패다.
- 달 착륙은 S/A/B만 승리로 인정한다.

## 7. 계산 예시

조건:

- 달 착륙 준비 50
- 엔진 70
- 로켓 65
- 궤도 70
- 달 착륙 이전 시도 1회
- 현재 환경 유성우 `-20`

계산:

```text
이전 단계 평균 = (70 + 65 + 70) / 3 = 68.33

20
+ 50 × 0.6 = 30
+ 68.33 × 0.2 = 13.67
+ 발사 경험 3
- 유성우 20
= 46.67

최종 성공 확률 = 47%
부분 성공 = 15%
실패 = 38%
```

같은 기술에서 최적 발사창이면 환경 보정이 `+10`이므로 성공 확률은 77%가 된다. 이 차이가 기다릴 이유를 만든다.

## 8. 결과 고정 시점

플레이어가 설계 단계에서 `발사`를 최종 선택하는 순간 아래 값을 모두 계산해 고정한다.

- 환경
- 맵 시드
- 목표 경로
- 로켓 설계 데이터
- 설계 적합도
- 성공 확률
- 난수
- 등급
- 사고 유형
- 사고 복구 여부
- 결과 지표

3D 시뮬레이션 씬을 다시 로드하거나 연출을 건너뛰어도 결과를 다시 뽑지 않는다. 발사 전 설계 단계에서 연구 화면으로 돌아간 경우에는 결과를 만들지 않는다.

## 9. 사고 선택 규칙

한 시험에는 주요 사고를 최대 하나만 사용한다.

우선순위:

1. 현재 환경과 직접 연결되는 사고가 있고 결과가 C/F이면 환경 사고 선택
2. 현재 환경과 직접 연결되는 사고가 있고 결과가 A/B이면 40% 확률로 복구 가능한 환경 사고 선택
3. 그 외에는 단계별 기술 사고 선택
4. S에서는 사고 없음 또는 20% 확률의 가벼운 근접 위기만 표시

예:

- 유성우 + 궤도 F → 유성 충돌
- 유성우 + 궤도 B → 유성 근접 통과 후 자세 복구
- 강풍 + 로켓 C → 상승 경로 이탈 후 시험 중단
- 안정 + 엔진 F → 연소실 압력 이상 또는 폭발

## 10. 공정성 원칙

- 플레이어에게 보이지 않는 확률 페널티를 넣지 않는다.
- 성공률 계산 내역을 설계 단계에서 보여준다.
- 설계 적합도는 목표 경로, 부품 위치, 힘, 방향과 연결되어야 한다.
- 실패 원인은 현재 환경 또는 낮은 기술과 연결되어야 한다.
- 90% 성공 확률에서도 실패할 수 있음을 UI에 명시한다.
- 환경 이벤트는 장식이 아니라 실제 확률과 3D 장면에 동시에 반영한다.
- 발사 버튼 이후 시뮬레이션 도중 버튼 입력으로 결과를 변경할 수 없다.
