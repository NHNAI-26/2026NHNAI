# 05. 테스트 공개성·설계 보정·성공 판정

> 상태: **확정**
> 이 문서는 날씨 삭제 후 발사 판정의 핵심 전략과 공정성을 정의한다.

## 1. 날씨 삭제

48시간 버전에는 날씨, 환경 예보, 발사창 보정을 만들지 않는다.

삭제되는 요소:

- 현재 분기 환경
- 향후 3분기 예보
- 강풍, 뇌우, 유성우, 태양 폭풍 같은 환경 상태
- 환경별 성공률 보정
- 환경 전용 사고 선택
- 날씨를 기다리는 발사창 전략

대기 행동은 유지한다. 대기는 좋은 날씨를 기다리는 행동이 아니라 정기 연구비를 받고 마감과 자금을 교환하는 행동이다.

## 2. 발사 판정 구성

발사 성공률은 아래 값으로 계산한다.

- 설치된 엔진 인스턴스들의 성능
- 직전 단계 최고 등급 보너스
- 발사 경험 보너스
- 설계 적합도 보정
- 테스트 공개성 보정

최종 달 착륙은 테스트 공개성을 선택하지 않는다.

## 3. 설계 적합도 보정

설계 단계에서는 이번 맵의 목표 경로와 플레이어 설계를 비교해 `designFit`을 `0~100`으로 계산한다. 이 값은 실제 궤도역학이 아니라 게임용 평가값이다.

```text
설계 적합도 보정 = round((designFit - 50) × 0.4)
```

따라서 설계 보정 범위는 `-20%p~+20%p`다. 설치된 엔진의 업그레이드 레벨, 냉각 안정성, 점화 신뢰도가 높을수록 같은 설계라도 더 높은 `designFit`을 받기 쉽다.

최소 평가 요소:

- 목표 경로와 예상 경로의 거리
- 필요한 방향과 설정한 힘 방향의 차이
- 단계별 필수 부품의 부착 위치
- 총 힘이 목표에 비해 부족하거나 과도한 정도
- 엔진 ON/OFF 타이밍이 목표 경로와 맞는 정도

## 4. 엔진 ON/OFF 타이밍

설계 단계에서 플레이어는 엔진을 언제 켜고 끌지 설정할 수 있다.

허용 방식:

- 초 단위 설정: `2.5초 ON`, `7.0초 OFF`
- 경로 지점 설정: `체크포인트 1 ON`, `목표 경로 70% 지점 OFF`

MVP에서는 둘 중 하나만 구현해도 된다. 둘 다 구현할 경우 같은 이벤트를 중복으로 만들 수 없게 한다.

타이밍 평가는 단순하게 한다.

```text
timingFit = 100 - timingError
```

`timingError`는 목표 ON/OFF 지점과 실제 설정 지점의 차이를 게임용 수치로 환산한다. 설치된 엔진의 점화 신뢰도가 높을수록 허용 오차가 커진다.

## 5. 테스트 공개성

최종 달 착륙을 제외한 엔진, 로켓, 궤도 발사는 아래 둘 중 하나를 선택한다.

| 방식 | 성격 | 성공률 보정 | 보상 | 실패 손실 |
|---|---|---:|---|---|
| 공개 테스트 | 하이 리스크 하이 리턴 | -10%p | 즉시 지원금·분기 연구비 변화 ×1.5 | 분기 연구비 -150 |
| 비공개 테스트 | 로우 리스크 로우 리턴 | +10%p | 즉시 지원금·분기 연구비 변화 ×0.5 | 분기 연구비 -50 |

공개 테스트는 언론과 후원 기관에 공개하는 큰 시험이다. 성공하면 지원이 크게 늘지만 실패하면 신뢰 손실도 크다.

비공개 테스트는 내부 검증이다. 실패해도 밖으로 크게 알려지지 않지만 성공해도 보상이 작다.

## 6. 성공률 계산

### 6.1 설치 엔진 성능

엔진은 프리셋 개체별로 관리한다. 설계 단계에서 배치된 엔진 인스턴스들의 프리셋 스탯과 업그레이드 레벨을 합산해 `InstalledEngineScore`를 만든다.

```text
InstalledEngineScore =
clamp(
    평균(설치 엔진별 프리셋 성능)
    + 엔진 개수 보정
    - 과중량 페널티,
    0,
    100
)
```

엔진 개수 보정은 많이 달수록 무조건 좋은 구조가 되지 않게 작게 둔다. 과중량 페널티는 엔진과 탱크를 너무 많이 단 설계를 막는 역할이다.

### 6.2 직전 단계 최고 등급 보너스

로켓, 궤도, 달 착륙은 별도 연구 수치를 갖지 않는다. 대신 직전 단계의 최고 등급을 검증 보너스로 사용한다.

| 최고 등급 | 보너스 |
|---|---:|
| S | +18 |
| A | +14 |
| B | +10 |
| C | +5 |
| F 또는 없음 | 0 |

| 발사 | 보너스 기준 |
|---|---|
| 엔진 | 없음 |
| 로켓 | 선택 엔진 프리셋의 엔진 테스트 최고 등급 |
| 궤도 | 로켓 테스트 최고 등급 |
| 달 착륙 | 궤도 테스트 최고 등급 |

### 6.3 공식

엔진 발사:

```text
성공률 =
20
+ 선택 엔진 프리셋 성능 × 0.8
+ 발사 경험 보너스
+ 설계 적합도 보정
+ 테스트 공개성 보정
```

로켓, 궤도, 달 착륙:

```text
성공률 =
20
+ InstalledEngineScore × 단계별 엔진 가중치
+ 직전 단계 최고 등급 보너스
+ 발사 경험 보너스
+ 설계 적합도 보정
+ 테스트 공개성 보정
```

달 착륙의 테스트 공개성 보정은 `0`이다.

단계별 엔진 가중치:

| 단계 | 가중치 |
|---|---:|
| 로켓 | 0.55 |
| 궤도 | 0.45 |
| 달 착륙 | 0.40 |

최종 성공률은 반올림한 뒤 `10~90`으로 제한한다.

발사 경험 보너스:

```text
min(해당 단계의 이전 발사 횟수 × 3, 9)
```

## 7. 결과 확률 표시

설계 단계 HUD에는 현재 설계와 테스트 방식 기준의 성공, 부분 성공, 실패를 모두 보여준다.

```text
성공: P%
부분 성공: min(15, 95 - P)%
실패: 나머지%
```

예시:

```text
로켓 공개 테스트 성공률: 54%
부분 성공: 15%
실패: 31%
```

최종 성공률이 90%여도 실패 확률은 최소 5% 남는다.

## 8. 결과 판정

1~100 정수 난수를 한 번 생성한다.

```pseudo
roll = RandomIntInclusive(1, 100)

if roll <= successChance:
    margin = successChance - roll

    if margin >= 50:
        grade = S
    else if margin >= 20:
        grade = A
    else:
        grade = B

else if roll <= min(successChance + 15, 95):
    grade = C
else:
    grade = F
```

- S/A/B는 완전 성공이다.
- C는 부분 성공이다.
- F는 실패다.
- 달 착륙은 S/A/B만 승리로 인정한다.

## 9. 계산 예시

조건:

- 설치 엔진 점수 70
- 로켓 테스트 최고 등급 B
- 궤도 이전 발사 1회
- 설계 적합도 72
- 공개 테스트 선택

계산:

```text
직전 단계 최고 등급 보너스 = 10

20
+ 설치 엔진 점수 70 × 궤도 가중치 0.45 = 31.5
+ 직전 단계 최고 등급 보너스 10
+ 발사 경험 3
+ 설계 보정 9
- 공개 테스트 10
= 63.5

최종 성공률 = 64%
부분 성공 = 15%
실패 = 21%
```

같은 조건에서 비공개 테스트를 선택하면 공개성 보정이 `+10`이므로 성공률은 84%가 된다. 대신 성공 보상은 절반이다.

## 10. 결과 고정 시점

플레이어가 설계 단계에서 `발사`를 최종 선택하는 순간 아래 값을 모두 계산해 고정한다.

- 맵 시드
- 목표 경로
- 로켓 설계 데이터
- 설치된 엔진 인스턴스 목록
- 엔진 설치 예약 비용
- 엔진 ON/OFF 타이밍
- 테스트 공개성
- 설계 적합도
- 성공률
- 난수
- 등급
- 사고 유형
- 사고 복구 여부
- 결과 지표

3D 발사 결과 화면을 다시 표시하거나 연출을 건너뛰어도 결과를 다시 뽑지 않는다. 발사 전 설계 단계에서 연구 화면으로 돌아간 경우에는 결과를 만들지 않는다.

## 11. 사고 선택 규칙

한 발사에는 주요 사고를 최대 하나만 사용한다.

우선순위:

1. 결과가 C/F이고 설계 적합도에서 가장 낮은 항목이 있으면 그 항목과 연결된 사고 선택
2. 결과가 A/B이면 복구 가능한 설계 사고 선택
3. S에서는 사고 없음 또는 20% 확률의 가벼운 근접 위기만 표시

예:

- 엔진 ON 타이밍 늦음 + 로켓 C → 목표 고도 미달 후 발사 중단
- 힘 방향 오차 + 궤도 B → 진입 각도 이탈 후 자동 보정
- 부품 위치 불량 + 엔진 F → 연소 안정 상실

## 12. 공정성 원칙

- 플레이어에게 보이지 않는 성공률 페널티를 넣지 않는다.
- 성공률 계산 내역을 설계 단계에서 보여준다.
- 설계 적합도는 목표 경로, 부품 위치, 힘, 방향, 엔진 ON/OFF 타이밍과 연결되어야 한다.
- 공개 테스트와 비공개 테스트의 보상·손실 차이를 발사 전에 보여준다.
- 발사 버튼 이후 시뮬레이션 도중 버튼 입력으로 결과를 변경할 수 없다.
