# 08. 로켓 발사

> 상태: **확정**  
> 역할: `발사` 버튼 이후 플레이어 입력 없이 결과를 보여주는 자동 3D 시뮬레이션  
> 적용 우선순위: 발사 이후의 연출, 사고, 등급 표현은 이 문서를 우선한다. 설계 입력과 조립 규칙은 `07_로켓_설계.md`, 엔진 스탯 수치와 확률 계산식은 `06_엔진_연구.md`를 우선한다.

## 1. 정의

발사 중에는 플레이어가 조종하는 실시간 물리 게임이 아니다. 설치된 엔진 인스턴스들의 프리셋 스탯, 설계 적합도, 테스트 공개성, 난수로 산출된 결과를 3D 장면에서 자동으로 재생하는 **연출형 시뮬레이션**이다.

복잡한 실제 물리 계산보다 다음 경험을 우선한다.

- 결과가 바로 드러나지 않는 긴장
- 설계 실수와 복구가 실제 3D 장면에 나타나는 볼거리
- 성공, 복구, 중단, 실패가 명확히 구분되는 연출

## 2. 발사 조건

- 선택한 발사 미션 해금
- 최소 1개 이상의 엔진 설치
- 발사 비용 900
- 설치한 엔진들의 예약 비용 확정 차감
- 현재 분기 1개 소비
- 설계 단계 진입과 설계 수정은 비용과 분기를 소비하지 않음
- 발사 버튼 선택 전에는 연구 단계로 복귀 가능

## 3. 결과는 발사 버튼 직후 고정

`발사` 버튼을 누른 시점에 `DesignData`로부터 `SimRunData`를 만들고 고정한다.

```text
missionId
year
quarter
mapSeed
targetPathId
launchVisibility
experienceBonus
designFit
installedEngines
committedEngineInstallCost
installedEngineScore
engineToggleSchedule
successChance
partialChance
failChance
roll
grade
incidentId
incidentRecovered
seed
generatedMetrics
```

자동 발사 화면은 `SimRunData`를 읽어 연출만 선택한다. 화면 내부에서 성공 여부를 다시 계산하지 않는다.

## 4. 발사 중 플레이어 입력

허용:

- 카메라 전환 버튼: 선택 사항
- `2배속`: P1
- `결과까지 건너뛰기`: 동일 발사를 한 번 이상 본 뒤 사용 가능
- 일시정지: 기본 시스템 메뉴

금지:

- 추력 조절
- 회전
- 경로 수정
- 사고 복구 버튼
- QTE
- 결과 재굴림
- 연료 또는 장비 선택
- 엔진 추가 또는 제거

## 5. 시퀀스

모든 자동 발사는 아래 6개 구간을 공유한다.

1. **브리핑**: 발사명, 날짜, 테스트 공개성
2. **카운트다운**: 3~5초
3. **정상 진행**: 점화, 이륙, 상승
4. **위험 구간**: 사고가 발생할 수 있는 시점
5. **결과 구간**: 목표 달성, 중단, 추락, 폭발
6. **결과 보고서 전환**

로켓 발사 기준 시간표:

| 시간 | 상태 | 연출 |
|---:|---|---|
| 0~4초 | 브리핑 | 발사명, 날짜, 테스트 방식 |
| 4~8초 | 카운트다운 | 발사대 조명, 3-2-1 |
| 8~13초 | 점화·이륙 | 연기 확산, 로켓 상승 |
| 13~24초 | 대기권 상승 | 고도·속도·자세 표시 |
| 24~32초 | 위험 구간 | 추력 저하, 엔진 타이밍 오류, 유도 오류 가능 |
| 32~38초 | 결과 | 목표 고도 달성, 중단 또는 추락 |

결과 텍스트를 시뮬레이션 시작 직후 보여주지 않는다. 최소한 정상 진행 구간을 거친 뒤 경고 또는 성공을 드러낸다.

| 발사 | 첫 재생 목표 | 재시도 시 2배속 |
|---|---:|---:|
| 엔진 | 20~25초 | 10~13초 |
| 로켓 | 30~40초 | 15~20초 |

카운트다운이 지나치게 길어 반복 플레이를 방해하지 않도록 한다.

## 6. 장면 구성

최소 에셋:

- 설계 단계에서 조립한 로켓
- 단순 발사대
- 목표 상승 경로 표시선
- 지상과 하늘 배경, 구름
- 엔진 불꽃과 연기
- 폭발 VFX
- 설계 오류 경고 VFX

엔진 시험에서 사용한 불꽃, 연기, 폭발을 재사용한다.

## 7. 텔레메트리

3D 화면에는 실제 계산값처럼 보이는 최소 지표를 표시한다. 이 값은 등급에 맞게 사전 생성한 연출용 값이다.

```text
ALTITUDE
VELOCITY
ATTITUDE
ENGINE STATUS
FUEL
TEMPERATURE
DESIGN FIT
```

원칙:

- 플레이어가 결과를 예측할 단서가 되어야 한다.
- 사고 직전 값이 비정상적으로 변화해야 한다.
- 성공 시 목표 기준을 넘는 모습이 보여야 한다.
- 결과 보고서의 수치와 모순되지 않아야 한다.

결과 보고서 항목: 최고 고도, 최대 속도, 평균 자세 오차, 사고 원인.

## 8. 엔진 스탯의 발사 중 반영

| 스탯 | 3D 장면과 텔레메트리에서의 작동 |
|---|---|
| 연료 탱크 용량 | 연료 게이지 소진 속도. 연료가 0이 되면 엔진 정지 연출로 전환한다 |
| 냉각 능력 | 온도 지표 상승률과 과열 계열 사고 발생 여부 |
| 최대 출력 | 상승 가속, 도달 고도, 추력 지표 |
| 점화 신뢰도 | 카운트다운 직후 점화 실패와 비행 중 재점화 실패 연출 |

스탯 정의와 상관관계는 `07_로켓_설계.md` 6절, 수치와 계산식은 `06_엔진_연구.md`를 따른다.

## 9. 사고

한 발사에는 주요 사고가 하나만 발생한다. 두 사고를 연쇄로 구현하지 않는다.

주요 사고로 계산하지 않는 것: 작은 스파크, 계기판 순간 경고, 카메라 흔들림, 통신 노이즈.

| ID | 사고 | 주 연계 설계 항목 | 결과 표현 |
|---|---|---|---|
| `IgnitionFailure` | 점화 실패 | 점화 신뢰도 부족 | 카운트다운 후 점화되지 않음 |
| `Overheat` | 과열 | 냉각 능력 대비 최대 출력 과다 | 온도 경고 후 추력 진동 또는 폭발 |
| `ThrustLoss` | 추력 손실 | 힘 부족 또는 OFF 타이밍 과다 | 불꽃 감소, 상승 둔화 |
| `FuelStarvation` | 연료 조기 소진 | 연료 탱크 용량 부족 | 상승 중 엔진 정지 |
| `GuidanceDrift` | 유도 오차 | 기술 사고 | 로켓이 서서히 기울어짐 |
| `StructuralStress` | 구조 진동 | 부품 위치 불량, 비대칭 배치 | 기체 흔들림과 경고 |
| `IgnitionTooEarly` | 조기 점화 | ON 타이밍 과도하게 빠름 | 경로 초반 이탈 |
| `CutoffTooLate` | 지연 차단 | OFF 타이밍 지연 | 목표 고도 초과 후 자세 불안정 |
| `Crash` | 추락·파괴 | F 결말 | 기울어 하강 후 폭발 |

## 10. 등급별 연출

| 등급 | 공통 연출 |
|---|---|
| S | 안정적인 진행, 강한 성공 연출, 선택적으로 근접 위기 1회 |
| A | 경미한 경고 발생 후 자동 복구, 목표를 여유 있게 달성 |
| B | 뚜렷한 문제 발생 후 가까스로 복구, 목표를 최소 기준으로 달성 |
| C | 목표 일부 달성 후 자동 중단·복귀·조기 종료 |
| F | 주요 장비 손상, 폭발, 추락 |

S/A/B는 서로 다른 전체 영상을 만들지 않는다. 성공용 기본 시퀀스를 공유하고 경고 강도, 카메라, 지표, 효과만 다르게 한다. C와 F만 별도 결말 분기를 둔다.

### S

- 거의 수직으로 안정 상승
- 목표 고도를 크게 초과
- 경고 없음 또는 짧은 경고
- 화면 밖으로 상승하며 성공

### A

- 경미한 자세 오차
- 자동 유도 시스템이 복구
- 목표 고도를 안정적으로 달성

### B

- 큰 흔들림 또는 일시적 추력 저하
- 목표 고도 직전에 복구
- 최소 기준을 넘긴 직후 발사 종료

### C

- 목표 고도의 70~95% 도달
- 안전 한계를 넘기기 전 자동 엔진 정지
- 기체 회수 또는 원거리 낙하로 처리
- `FLIGHT ABORTED`

### F

- 발사대 점화 실패
- 상승 직후 유도 상실
- 구조 파괴 또는 추락
- 폭발 연출

## 11. 카메라

- 3~5개의 고정 구도를 사용하고 자유 카메라는 만들지 않는다.
- 전환은 미리 정한 시간 또는 시뮬레이션 상태에 의해 자동 실행한다.
- 위험 발생 직전에는 텔레메트리 또는 기체 클로즈업으로 긴장감을 높인다.
- 실패 순간은 한 번 명확하게 보여주되 과도한 슬로모션은 사용하지 않는다.
- 결과를 알아보기 어려운 원거리 구도만 사용하지 않는다.

구도 목록:

1. 발사대 전체
2. 노즐과 연기
3. 로켓 추적 카메라
4. 측면 원거리 카메라
5. 실패 시 지면 또는 광각 카메라

## 12. 물리와 구현 축소선

허용:

- 실패 시 로켓에 Rigidbody를 활성화해 기울거나 추락
- 폭발 시 파편 또는 단순한 힘 적용
- 엔진 불꽃과 연기 파티클
- 카메라 흔들림

만들지 않음:

- 단 분리
- 정확한 추력 계산, 공기저항, 실제 연료 질량 변화
- 궤도역학, N-body 중력, 실제 대기권 모델
- 실제 비행 경로 계산 — 성공 경로는 설계 데이터에서 고른 애니메이션 곡선을 사용한다
- 로켓 내부와 승무원 장면

설계 평가는 목표 경로와 예상 경로의 단순 비교를 사용한다.

## 13. 완료 기준

- 같은 `SimRunData`면 같은 등급과 사고를 재생한다.
- 발사대에서 상승까지 한 흐름으로 보인다.
- 설계 오류와 엔진 스탯 약점이 성공률뿐 아니라 장면에도 반영된다.
- 발사 중 플레이어 조작이 결과를 바꾸지 않는다.
- S/A/B/C/F의 결말을 시각적으로 구분할 수 있다. 특히 B의 가까스로 성공과 C의 조기 중단이 구분된다.
- 실패 시 로켓이 단순히 사라지지 않고 원인을 볼 수 있다.
- 결과 지표가 등급과 모순되지 않는다.
- 결과 보고서로 돌아온 뒤 연구비와 미션 기록이 정확히 반영된다.
- 건너뛰어도 결과 적용이 한 번만 일어난다.
