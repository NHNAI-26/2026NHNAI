# 11. UI·UX 화면 설계

## 화면 구성

1. 타이틀
2. 프로젝트 운영
3. 연구 미니게임
4. 로켓 설계
5. 발사 시뮬레이션
6. 결과 신문 또는 내부 메일
7. 승리·패배

## 프로젝트 운영 화면

상단에는 날짜, 현재 연구비와 분기 연구비를 표시한다. 엔진 영역에는 프리셋별 완성도와 네 스탯을 표시한다. 미션 영역에는 잠금, 완료, 발사 횟수와 실제 목표 조건을 표시한다.

이 화면에서 연구, 집중 연구, 새 엔진 개발, 대기와 열린 미션의 설계 진입을 선택한다.

## 로켓 설계 화면

- 미션 목표와 목표 구역
- 엔진 프리셋 목록과 실제 스탯
- 엔진 설치·제거
- 장착 방향
- ON/OFF 시간
- 설계·설치 비용
- 공개·비공개 선택
- 발사 버튼

결과를 예측하거나 하나의 설계 품질값으로 축약하지 않는다. 플레이어는 실제 물리 수치와 목표를 보고 설계한다.

## 발사 확인

확인창에는 미션 목표, 설치 엔진, 작동 시간, 총비용과 공개 여부만 표시한다. 확인 뒤 설계를 잠그고 시뮬레이션으로 이동한다.

## 발사 HUD

HUD는 미션 목표와 실제 텔레메트리를 표시한다. 화면을 가리지 않는 범위에서 고도, 거리, 속도, 체류 시간, 연소 시간, 연료와 온도를 미션별로 선별한다.

## 결과 화면

결과 매체에는 아래 정보를 표시한다.

- 성공 또는 실패
- 실제 종료 사유
- 핵심 텔레메트리
- 비용과 이벤트의 실제 증감
- 다음 미션 해금 또는 최종 결과

색만으로 결과를 구분하지 않는다. 결과 매체를 다시 열어도 정산은 반복되지 않는다.

## 승리와 패배

- 최종 미션 성공: 성공 연출과 특별호 뒤 승리 화면
- 기간 만료 전 최종 성공 없음: 실패 특별호 뒤 패배 화면

## 사용성 규칙

- 잠긴 행동에는 구체적인 이유를 표시한다.
- 실제 값과 표시값의 단위를 통일한다.
- 버튼 상태가 비용, 잠금과 시뮬레이션 상태를 즉시 반영한다.
- 발사 중 중요한 텔레메트리가 서로 겹치지 않는다.
