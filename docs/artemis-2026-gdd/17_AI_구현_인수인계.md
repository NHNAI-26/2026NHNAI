# 17. AI 구현 인수인계 명세

> 기준일: 2026-09-06
>
> 구현자는 이 문서와 `18_확정사항_및_변경금지선.md`를 먼저 따른다.

## 1. 제품 정의

플레이어가 연구한 엔진으로 로켓을 조립하고 발사 전 방향과 가동 시간을 정한 뒤, 실제 Unity 물리 비행으로 여섯 미션을 순서대로 통과하는 프로젝트 운영 게임이다.

## 2. 불변 조건

- 발사 결과는 시뮬레이션 실행 전 확정하지 않는다.
- 미션 평가는 실제 비행 상태와 텔레메트리만 사용한다.
- 결과 모델은 성공 여부와 종료 사유를 중심으로 한다.
- 이전 미션 성공으로 다음 미션을 연다.
- 최종 미션 성공으로 게임에서 승리한다.
- 공개 여부는 결과 이후 이벤트와 표시 매체만 바꾼다.
- 엔진 스탯과 설계 입력은 물리에 직접 반영한다.
- 실행 결과를 덮어쓰는 종합 점수나 숨은 보정치를 만들지 않는다.

## 3. 핵심 데이터

```text
EnginePresetState
  id
  unlocked
  completion
  fuelCapacity
  cooling
  maxThrust
  ignitionReliability

MissionLaunchState
  missionId
  unlocked
  completed
  attemptCount

LaunchResult
  missionId
  succeeded
  terminationReason
  telemetry
  visibility
  usedEnginePresetIds
```

`completion`은 연구 가능 잔여량을 제한하는 값이다. 엔진 성능 단계를 뜻하지 않으며 해금 조건으로 쓰지 않는다.

## 4. 발사 처리 순서

```text
validate_design
reserve_cost
load_simulation
apply_engine_stats_and_design
run_physics
collect_telemetry
evaluate_mission_conditions
create_launch_result
unlock_next_mission_on_first_success
apply_one_post_launch_event
show_report
```

평가기 결과를 받은 뒤 다른 방식으로 성공 여부를 다시 계산하지 않는다. 결과 적용은 한 번만 실행한다.

## 5. 미션 평가 계약

- `StaticFire`: 고정 상태에서 요구 연소 시간을 채우고 과열 또는 점화 실패가 없어야 한다.
- `LowAltitude`: 낮은 목표 고도에 실제 도달한다.
- `HighAltitude`: 높은 목표 고도에 실제 도달한다.
- `TargetZone`: 목표 구역에 실제 진입한다.
- `ZoneHold`: 목표 구역에서 요구 시간을 실제 체류한다.
- `LowPowerZoneHold`: 체류 조건과 제한된 자원 사용 조건을 함께 만족한다.

정확한 목표값은 미션 설정 데이터에서 읽는다.

## 6. 결과와 UI

발사 전 UI:

- 미션 목표
- 설치 엔진의 실제 수치
- 장착 방향과 ON/OFF 시간
- 비용
- 공개 여부

발사 후 UI:

- 성공 또는 실패
- 구조화된 종료 사유
- 실제 텔레메트리
- 이벤트와 실제 정산값

예측 결과나 결과 품질 표식은 표시하지 않는다.

## 7. 마이그레이션 지침

기존 코드에 과거 결과 모델의 필드나 분기가 남아 있으면 새 기능이 그 필드에 의존하지 않게 한다. 호환용 필드는 호출부와 직렬화 참조를 확인한 뒤 별도 코드 정리 작업에서 제거한다.

특히 다음 동작을 새 구현의 근거로 삼지 않는다.

- 발사 전 결과 선택
- 이전 기록에 따른 비행 보너스
- 성공 시 결과 품질 세분화
- 결과 품질에 따른 고정 보상
- 설계값을 하나의 결과 보정치로 환산

## 8. 완료 조건

- 여섯 미션이 실제 물리 조건으로 성공과 실패를 구분한다.
- 첫 성공 시에만 다음 미션 해금이 발생한다.
- 공개 여부 변경이 같은 발사의 물리 결과에 영향을 주지 않는다.
- 결과 보고서 수치가 해당 실행의 텔레메트리와 일치한다.
- 결과 적용을 재호출해도 자원, 해금, 이벤트가 중복 반영되지 않는다.
